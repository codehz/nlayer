# v3

本文件是 v3 的产品范围和开发计划。v1、v2 的产品面与验收不变（`docs/v1.md`、`docs/v2.md`）。v3 只从 `AGENTS.md` 的「以后要做」里取下面列出的项：Nav（栈与模态）、pan / pinch / rotation 手势、列表与滚动的第二层（下拉刷新、分页与吸附、列表结构）。没列出的仍留在那一档。永久不做、不预承诺不因 v3 改变。实现上必需的小接口（无窗口的栈/模态模型、`back` / `drag` / `dragAndHold` / `drop` 测试步骤、内部的 `reduceMotion` 环境位）算在对应项里，不单列。

## 目标

v2 让一个真实应用能写出来、发出去。v3 让它有真实应用的结构：多屏与原生返回、可拖动 / 缩放 / 旋转的界面、会话式的列表。

进 v3 的判断仍是 v2 那条：应用没有它就得自己搭一层原生代码，或三端行为不一致。

实现照 `../nsh`：只搬它已经有的三端实现，不在 v3 里新设计 nsh 没有的语义。同一行为 nsh 只在部分平台做到的，按它已有的做法搬，不为对齐另写一套。

## 完成的标准

同一个 TSX 应用（`examples/gallery` 改造成 Nav 应用）用 v3 的 CLI 在三端跑起来，并满足：

1. 导航：首页 → 详情 push / pop；iOS 侧滑返回、Android 返回键与预测返回、web 浏览器后退都能出栈；`popOnSwipe` / `popOnBack` / `onBackPress` / `onDismiss` 按 nsh 语义；栈到根后返回才落到 `BackHandler`，再没人处理走平台默认。
2. 头部：iOS / Android 是系统头（`title`、`headerStyle`、`headerTransparent`）；web 显示应用画的 `header` 槽与 `headerLeft` / `headerRight` / `headerTitle`；页面内容从头的下方开始，insets 进 `env()`。
3. 模态：`Dialog` 的打开与关闭、背景点击关闭、Android 返回 / Escape 关闭、iOS 下滑关闭、web 后退关闭；`animation="slide" | "fade" | "none"`。
4. 手势：`pan` / `pinch` / `rotation` 驱动动画值（v2 的图），`onPanStart` / `onPanEnd`、`onPinchStart` / `onPinchEnd`、`onRotationStart` / `onRotationEnd`；松手速度能直接喂 `spring`；卡片在纵向 `Scroll` 里的横向拖动按各平台已有的协商行为；无窗口用 `drag` / `dragAndHold` / `drop` 断言位移与结束。
5. 列表：下拉刷新（`refreshing` / `onRefresh` / `pullValue` / `refreshIndicator`）；`pagingEnabled` 与 `snapToInterval` / `snapToOffsets` / `snapToAlignment`；`stickyHeaderIndices`、`inverted`、`maintainVisibleContentPosition`、`viewport="parent"`、`viewabilityConfig` / `onViewableItemsChange`；5000 行仍复用。
6. 测试：`nlayer test` 的无窗口模型有栈、屏幕、模态、insets、`back`；`--target` 的输入仍按 v1 的规则走宿主。
7. 打包：`nlayer package --target web|ios|android` 的产物仍能启动并跑上面的导航与手势；不新增 crate。

`nlayer test` 默认无窗口；`nlayer test --target web|ios|android` 用宿主自己的输入。pinch / rotation 没有无窗口步骤（nsh 也没有），只在 `--target` 上冒烟；不做设备像素断言（同 v1）。

## 产品面

### 导航

```tsx
import { Dialog, NavPage, NavStack, createNavStack } from "@nlayer/ui";

type Route = { name: "inbox" } | { name: "message"; id: number };
const nav = createNavStack<Route>([{ name: "inbox" }]);

<NavStack state={nav} style={{ flex: 1 }}>
  {(route) => (
    <NavPage title={title(route)} header={<Header />}>
      <Body route={route} />
    </NavPage>
  )}
</NavStack>;
```

- 路由归应用：`createNavStack(routes)` 返回 `routes()`、`push`、`pop`、`popToRoot`、`replace`、`setRoutes`、`remove`。同一个 route 值可以压多次，每次是一页。页在栈里保持挂载与状态。
- `NavStack` 的 children 按 route 调一次（push 时），返回这一页的内容；第二个参数 `index()` 是它当前的位置。返回 `NavPage` 才有选项，别的值包一层默认页。
- 容器是原生的：iOS 是 `UINavigationController`，Android 是栈视图加 toolbar，web 由 mounter 自己排。core 只按栈的尺寸排每一页、回报 insets、转递返回请求；转场与返回手势由容器给。
- `NavPage`：`title`、`header`、`headerVisible`、`headerBackVisible`、`headerLeft` / `headerRight` / `headerTitle`、`headerStyle`（`backgroundColor` / `color` / `tintColor`）、`headerTransparent`、`animation`（`default` / `fade` / `none`）、`popOnSwipe`、`popOnBack`、`onBackPress`、`onDismiss`、`style` / `class`。所有选项是响应式的。
- iOS / Android 显示系统头；web 显示应用的 `header` 槽。两样都给，三端都像原生。
- 用户原生 pop 后路由已被移除，`onDismiss` 在之后报；应用维护的其它状态在 `onDismiss` 里清。
- 返回优先级：栈先消费（`popOnBack` / `popOnSwipe` 决定是否 pop），`onBackPress` 总是先报；栈到根后落到 `BackHandler` 的监听；没人处理走平台默认（Android 退到后台，web 正常后退，iOS 没有系统返回，不触发）。
- web：栈与模态占浏览器历史条目（照搬 nsh 的 `nsh.js` 段）。v2 说的「应用自己 `pushState`」只对不用 `NavStack` 的应用成立。
- `Dialog`：`open`、`onOpenChange`、`onOpen`、`onClose`、`onCancel`、`children`、`style` / `class`、`backdropStyle` / `backdropTestID`、`animation`（`slide` / `fade` / `none`）、`closeOnBackdropPress` / `closeOnSwipe` / `closeOnEscape`，照搬 nsh。

v3 不做：TabBar；`headerClass`（Tailwind 不在 v3，class 解析器仍为空）；iOS 的 `headerLargeTitle` / `headerBackTitle` / `ios.headerRightSystemItem`；每屏 `statusBar`；web 上 Nav 之外的历史记录（应用仍自己 `pushState`）。

### 手势

```tsx
const x = createAnimatedValue(0);
const y = createAnimatedValue(0);
const scale = createAnimatedValue(1);
const angle = createAnimatedValue(0);

<View
  pan={{ x, y }}
  pinch={{ scale }}
  rotation={{ angle }}
  onPanEnd={(e) => {
    x.spring(0, { velocity: e.velocity.x });
    y.spring(0, { velocity: e.velocity.y });
  }}
  style={{ translate: [x, y], scale }}
/>;
```

- 值绑定进 v2 的动画图：`pan={{ x?, y? }}` 是点，`pinch={{ scale? }}` 是倍数，`rotation={{ angle? }}` 是角度。开始手势时读取当前值，进行中的动画停在那里；之后的位移加在这些值上。
- 事件：`onPanStart` / `onPanEnd`（载荷有 translation、velocity、绑定的当前值）、`onPinchStart` / `onPinchEnd`、`onRotationStart` / `onRotationEnd`。速度单位：pan 是点每秒，pinch 是倍率每秒，rotation 是度每秒；都可以直接喂 `spring` / `timing` 的 `velocity`。
- 手势属性进所有宿主，规则同 `onPress`。
- pan、pinch、rotation 可以在同一个宿主上同时进行。
- 与 `Scroll` 的协商按各平台已有的实现：单轴绑定时按方向判定（横向拖动不抢纵向滚动）；iOS 的滚动衔接是 iOS 的 `PanScrollHandoff`；web 照 nsh 的 pointer 实现；Android 照 `ScrollBox` / `TouchTracker`。nsh 没有做到同一行为的平台，不新写一套。
- 只做原生手势值绑定：不搬 responder 协商、`PanResponder`、原始 `onTouch*`。

v3 不做：responder / `PanResponder` / `onTouch*`；`panActivation`；手势组合器；自定义识别器；`decay`（v2 已排除）。

### 列表与滚动第二层

- 刷新：`refreshing`、`onRefresh`、`pullValue`（动画值，0 起、拉动增大）、`refreshIndicator: { height }`（应用自己画指示器，平台 spinner 隐藏）。`Scroll` 与 `List` 都支持。
- 分页与吸附：`pagingEnabled`、`snapToInterval`、`snapToOffsets`、`snapToAlignment`（`start` / `center` / `end`）、`disableIntervalMomentum`、`decelerationRate`（`"normal"` / `"fast"` / 数值）。
- 列表结构：`stickyHeaderIndices`（单列、非 `inverted`）、`inverted`、`maintainVisibleContentPosition`（含 `autoscrollToBottomThreshold`）、`viewport="parent"`（列表放在外层 `Scroll` 里）、`viewabilityConfig` / `onViewableItemsChange`（载荷 `first` / `last`）。
- 滚动偏移仍同时进核心与 JS；v2 的窗口、回收、`onLoadMore`、`scrollToIndex` / `scrollToEnd` 不变。

v3 不做：缩放的整套 prop 与 `zoomTo`（`minimumZoomScale` / `maximumZoomScale` / `zoomScale` / `bouncesZoom` / `zoomable` / `centerContent`）；`bounces`、`contentInset`、`contentOffset`、`scrollEventThrottle`、`scrollbar` 主题；下拉刷新的手势层之外的物理（跟手动画、弹簧回弹由平台自己的实现决定）。

## 公开模块

不变：只有 `@nlayer/runtime` 和 `@nlayer/ui` 两个原生模块，互不重导出。

`@nlayer/ui` 增加：`createNavStack`、`NavStack`、`NavPage`、`Dialog`；所有宿主的 `pan` / `pinch` / `rotation` 与 `onPanStart` / `onPanEnd` / `onPinchStart` / `onPinchEnd` / `onRotationStart` / `onRotationEnd`；`Scroll` 与 `List` 的刷新、分页吸附与列表结构 prop。

`@nlayer/test` 增加：`back()`、`drag(selector, x, y)`、`dragAndHold(selector, x, y)`、`drop()`；无窗口模型支持栈、屏幕、模态与 `back` 的落点。

类型仍由 `nlayer-bundler` 的 `gen-types` 生成到 `packages/`。

## 开发计划

每个里程碑是一个能合的切片：行为能跑，测试是绿的，没有空实现。改动到的 crate 跑 `cargo test -p`；动到 TSX、引擎或宿主的切片还要 `nlayer test` 绿。

### 顺序

M1 先合，它是其余切片的协议。M2、M3 与 M4、M5 互不依赖，可以并行；M4 只碰手势通道，M5 只碰滚动与列表。M6 的栈 / 模态模型在 M1 之后即可开始，`drag` / `dragAndHold` / `drop` 等 M4 的指针入口，验收应用等 M2–M5 全绿。iOS 的根控制器改动（M2）与 v2 的 safe area / 键盘 inset 共用回归，放 M2 验收。

## 不进 v3

| 项 | 为什么 |
|---|---|
| TabBar | 第二个容器组合层，等栈与模态稳定 |
| Canvas | 布局尺寸事件加绘图 op 加三端重放，XL |
| Video / WebView | 各自的宿主生命周期与 JS 桥，与导航应用独立 |
| SVG / GIF | 原生解码依赖与播放生命周期 |
| `Text` 文本选择、可选中 `View`、行内视图、`href` | 三端各一套选择与手势栈 |
| Tailwind | 5k 行解析器，与 typed style 重复；v3 的 `class` 仍为空解析器 |
| HMR | 需要 CJS 工厂式开发包和状态保留，XL |
| WebSocket / fetch cookie / `crypto.subtle` | 传输层与安全语义要单独设计 |
| 嵌入 ABI、签名包、`nlayer check`、桌面、shader、自定义字体 | 永久不做或不预承诺 |
| 设备像素对齐断言 | 仍不做 |

## 风险与决定

- **iOS 根控制器**：现在的根是普通 `UIViewController`，导航要换成能承载 `UINavigationController` 的根。safe area、状态栏、键盘 inset、`run` 与打包两条启动路径都要回归；这是 M2 的主要风险。
- **web 的历史有两个消费者**：Nav 的深度与 v2 `BackHandler` 的 `popstate` 都听浏览器历史，必须只有一个来源：栈先消费，栈到根后才报 `BackHandler`。否则后退一次既 pop 又触发应用监听。
- **返回优先级改变 v2 行为**：`BackHandler` 只在栈到根后收到；v2 的应用若自己监听返回并 pop 状态，要改成用 `NavStack`。v3 文档与 `BackHandler` 的说明要同时写明。
- **手势与滚动协商各平台不同**：nsh 的滑动衔接是 iOS 专属，web 与 Android 各有自己的实现。验收只覆盖各平台已有的行为，不为对齐新写一套。
- **无窗口模型的保真度**：`back_target` 是平台差异的抽象；无窗口只断言可移植语义（栈深、可见页、insets、关闭原因），不覆盖转场帧与设备像素。
- **列表的 `viewport="parent"`**：与 v2 的 cell 独立布局根叠加，窗口与内容尺寸的来源要只有一个（外层滚动）。先用 M5 的无窗口测试钉住，再接宿主。
- **header 高度回传**：web 的 header 是应用画的，高度由 core 测出来后回传 `set_screen_header`；回传晚一帧会让 insets 跳一下，首帧按估算高度排。
- **不搬 `nsh-core/src/navigation.rs`**：那是桌面后端的无视图树时机引擎；nlayer 没有桌面后端，web 与无窗口各自实现。
- **`reduceMotion`**：nsh 的 `Dialog` 转场读环境位；nlayer v2 没有这个 API。v3 只在内部给一个环境位（不导出），低层动画仍按写好的播放。
