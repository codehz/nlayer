# v7

本文件是 0.7.0（v7）的产品范围和开发计划。v1 到 v6 的产品面与验收不变，只有一条例外：v5 表里「阴影、渐变、ring 不绘制」由本版替换。`ring` / `inset-ring` / `ring-offset` 降成 `boxShadow` 层，跟阴影一起画。filter、backdrop、mask、blend、outline、glass、transition、内置 keyframes、文字阴影仍不画。v7 从 `AGENTS.md` 的「以后要做」里取阴影和渐变的绘制，以及因此能生效的那些 utility。没列出的仍留在那一档。永久不做、不预承诺不因 v7 改变。

## 目标

v6 让保存后留住正在跑的应用。v7 让已经写进样式、解析器也已经收下的阴影和渐变在三端画出来。

绘制从 nsh 拷，不重写算法。iOS 用 `CAGradientLayer`（轴向、径向、圆锥），Android 用 `Decor` 的阴影和 `SweepGradient`，web 用 CSS 的 `box-shadow` 和 `background-image`。模糊半径的换算照 nsh，不另调。核心里缺的 `Gradient::unrolled_stops` 从 nsh 补回，给 iOS 用；Android 沿用 `Decor.Gradient.place` 里的展开；web 的 repeating 交给 CSS。

三端同一语义，有一处故意不照 nsh 的 web：普通视图的外阴影不被自己的 `overflow: hidden` 裁掉。nsh 的 iOS 和 Android 已经是这样，nsh 的 web 用 `overflow: clip` 会把阴影一起裁掉。

## 完成的标准

同一个 TSX 应用（`examples/gallery` 加一屏）用 v7 的 CLI 在三端跑起来，并满足：

1. 内联 `boxShadow` 和 `backgroundImage` 画出来。多层、`inset`、spread（含负的）、模糊、`currentColor`、线性（含跟盒子走的角）、径向、圆锥、`repeating`、长度色标都在。没写颜色的阴影层是文字色。渐变盖在 `backgroundColor` 上，透明色标透出底色。
2. 普通视图（`View`、`Text`、`Image`、`Input`，以及导航里不是滚动容器的视图）设了 `overflow: hidden` 时，外阴影仍在盒子外，裁的是子内容。`Scroll` 和 `List` 自己的外阴影被裁掉。祖先的裁切仍然生效。
3. `activeStyle` / `hoverStyle` / `focusStyle` 里非空的阴影层替换基础阴影，非空的渐变替换基础渐变。没写的那一份留着。`boxShadow: "none"` 和空的 `backgroundImage` 清不掉基础，和这个槽里透明背景清不掉背景色一样。Active 压过 hover，hover 压过 focus。这些槽仍只绘制，不改布局。
4. class 生效：`shadow-*`、`shadow-<color>`、`shadow-*/20`、`inset-shadow-*`、`ring-*`、`ring-offset-*`、`inset-ring-*`、`bg-linear-*`、`bg-radial`、`bg-conic`、`from-*`、`via-*`、`to-*`，以及合法的任意值。`hover:shadow-none` 清掉阴影，因为它重算主样式，不走状态槽。`shadow-md blur-sm` 里阴影生效，`blur-sm` 仍警告。一条 utility 混有过不了门的声明时，整条仍丢弃。
5. 不画、也不新增警告的：`textShadow`、`filter`、`backdropFilter`、`maskImage`、`mixBlendMode`、`outline*`、`glassEffect`、`transition*`、`animation*`。内联仍是静默忽略。class 仍是 `unsupported classes`。绑到这些键上的动画值仍忽略。阴影和渐变也不能绑动画值。
6. 测试：无窗口断言 mount 样式里的层和色标、状态槽里的那份绘制、以及阴影不改布局。web 的编码测试断言 `box-shadow` / `background-image`，以及「有外阴影又 `overflow: hidden`」时裁切不在阴影那一层。不做设备像素断言。三端各一条冒烟：这屏能打开。
7. 打包：`nlayer package --target web|ios|android` 的产物仍能启动并跑这屏。不新增 crate，不新增公开模块，不改 `nlayer.json`。

## 产品面

### 画什么

画 `ViewStyle.effects` 里的 `box_shadows` 和 `background_images`。不画同一结构里的 `filters`、`backdrop_filters`、`mask_images`。

`boxShadow` 是 CSS 层：偏移、模糊、spread、颜色、`inset`，多层，CSS 顺序（先写的在上）。字符串和 `[{ x, y, blur, spread, color, inset }]` 已经是同一份 IR。

`backgroundImage` 只画渐变：`linear-gradient`、`radial-gradient`、`conic-gradient` 和它们的 `repeating-` 形式，多个用逗号分开，先写的在上。色标可以是百分比或长度；圆锥的色标是角度。核心在挂上之前把 `currentColor` 和 OKLab / sRGB 插值展开成色标，宿主不再插值。

阴影和渐变画在元素的盒子上，沿圆角。不画字形。`textShadow` 不是这版。

### 层

自下而上：外阴影，背景色，渐变，内阴影，边框，子内容。内阴影在盒子内、边框下。外阴影可以画出盒子。

### 裁切

非滚动视图有可见的外阴影，并且 `overflow: hidden`：裁切挪到内容层，阴影留在外层。没有外阴影时，裁切保持现在的写法（web 仍是 `overflow: clip`，避免浏览器把盒子当滚动容器）。

`Scroll` 和 `List` 始终裁自己的内容，外阴影没有。这是 nsh 的滚动视图，不是新物理。

### 状态槽

合成在宿主，不进布局。只看两份列表各自是否非空，不看整个 `Effects` 是不是空的：状态样式里只写了阴影时，基础渐变还在。状态样式里的 filter 不绘制，也不清掉阴影或渐变。

class 的 `hover:` / `active:` / `focus:` 仍由引擎重算主样式。`hover:shadow-md` 和 `hoverStyle={{ boxShadow }}` 两条都通，清掉只走 class。

### class 的门

`part_allowed` 放行阴影、内阴影、ring（含 offset、inset、颜色、透明度）和渐变（含 `bg-none`、任意渐变、`from` / `via` / `to` 及位置）。`key_allowed` 放行 `BoxShadow` 和 `BackgroundImage`。滤镜、drop-shadow、文字阴影、skew、transition、animate 继续拒绝。条件门不动：`dark:`、断点、`group`、平台、`motion-*` 仍整条不生效。

## 公开模块

不变。只有 `@nlayer/runtime` 和 `@nlayer/ui`。类型里已有 `boxShadow` 和 `backgroundImage`，不新增导出。

## 开发计划

每个里程碑是一个能合的切片：行为能跑，测试是绿的，没有空实现。改动到的 crate 跑 `cargo test -p`；动到 TSX、引擎或宿主的切片还要 `nlayer test` 绿。

### M1 iOS

`Gradient::unrolled_stops` 从 `nsh-core` 的 `effects.rs` 补进 `nlayer-core`。`visual.rs` 的阴影和 `shape_gradient` 裁进视图绘制：轴向、径向、圆锥，repeating 走 `unrolled_stops`。内容层裁切照 `draws_outside`：有外阴影的普通视图不把阴影裁掉。状态合成照「产品面」。`Scroll` 仍整层裁。

来源：`nsh-platform-ios/src/visual.rs`、`decor.rs` 里 `draws_outside` 和内容层那一段，`nsh-core/src/effects.rs` 的 `unrolled_stops`。不搬 outline、滤镜、backdrop、mask。

### M2 Android

`Decor` 的外阴影、内阴影和 `Gradient.place`（含圆锥的 `SweepGradient` 和 repeating 展开）裁进来。`Box` 在「要裁切且有外阴影」时把子视图放进内容层。状态合成同上。`Scroll` 仍裁。

来源：`nsh-platform-android` 的 `Decor.java`、`Box.java` 的内容层。模糊半径用 nsh 的 `shadowRadius`，不改系数。

### M3 web

编码出 `box-shadow` 和渐变的 `background-image`，照 `nsh-platform-web/src/encode.rs` 里这两段。状态规则只写出非空的那份列表，空列表不写 `none`。有外阴影又 `overflow: hidden` 时，裁切在内容层，不照 nsh web 把 `overflow: clip` 写在阴影那一层。没有外阴影时保持现在的 `overflow: clip`。

### M4 生效门

三端都能画之后，打开「class 的门」里列出的 part 和 key。打开之前 class 仍警告且不写入样式，避免「不再警告但还没画」。核心测试覆盖完成标准 4 和 5 里能在无窗口看的部分。

### M5 样例

`examples/gallery` 加一屏：一张有圆角、外阴影、`overflow: hidden` 的卡片；一处透出底色的线性渐变；一处径向或圆锥；一处内阴影或 `ring`；一处 `hover:shadow-*` 或 `hoverStyle` 换阴影。保留已有的屏。无窗口测试覆盖完成标准里能断言的部分。三端各一条冒烟。

### 顺序

M1、M2、M3 互不依赖，可以并行。`unrolled_stops` 只跟 M1 合，M2、M3 不改它。M4 等三端。M5 等 M4。

## 不进 v7

| 项 | 为什么 |
|---|---|
| `textShadow`、字形阴影 | 另一条文本绘制。盒子阴影不是它 |
| `filter`、`backdrop-filter`、`drop-shadow`、`mask`、`mix-blend`、`outline-*`、glass | 仍不画。class 继续警告 |
| `transition*`、`animate-*`、阴影或渐变上的动画值 | 动效图没有这些绑定。v2 的四个绑定不变 |
| 状态槽里的 `none` 清掉基础阴影或渐变 | 和这个槽里清不掉背景色一样。要清用 `hover:shadow-none` |
| `Scroll` / `List` 自己的外阴影 | nsh 的滚动视图整层裁，不另做一层 |
| 设备像素断言 | 仍不做 |
| 主题配置、`dark:`、断点、`group` | 不是绘制。v5 的门不动 |
| 缩放、布局动画、WebSocket、`crypto.subtle`、SVG、GIF | 仍是以后要做，不是这版的缺口 |

## 风险与决定

- **以前静默忽略的内联阴影和渐变会开始画。** 以前警告的 `shadow-*`、`ring-*`、`bg-linear-*` 一类会开始生效。这是本版替换 v5 那一行的原因。
- **web 的裁切和 nsh 不同。** 只在「有外阴影且 `overflow: hidden`」时加内容层。其余盒子仍用 `overflow: clip`。
- **状态槽不记 key 写过没有。** 空列表和没写无法区分，所以只有非空才盖住。`Effects` 是一整块，合成必须按阴影列表和渐变列表分开，不能整块替换。
- **不写一半几何。** 圆锥、repeating、inset、spread 都在。少画一种会让已经解析成功的 IR 继续静默。
- **Android 的模糊不是 CSS 高斯。** 照 nsh 的换算拷，不在这版把三端修成同一个像素。
- **门晚于绘制。** 宿主还没画的时候打开门，class 会不再警告却仍然看不见。
