# v6

本文件是 0.6.0（v6）的产品范围和开发计划。v1 到 v5 的产品面与验收不变，只有一条例外：v1 写的「`run` 监视 TSX 和资源，重建后重启引擎，状态丢掉」由本版替换。v6 从 `AGENTS.md` 的「以后要做」里取 HMR，以及 `nsh-dev` 协议里给现有测试步骤用的那一截通道。没列出的仍留在那一档。永久不做、不预承诺不因 v6 改变。

应用面的 `WebSocket` 仍不做。开发服务器自己用的套接字不是这条 API。nsh 的菜单、剪贴板、`host.send`、对话框、keymap、拖文件、截图、canvas 查询不进协议。

## 目标

v5 让样式能用 class 写。v6 让 `nlayer run` 改完保存后留住正在跑的应用。

实现照 `../nsh` 的开发包、`__nsh_hot`、补丁通道，以及测试会话里下发步骤的方式。不按同一设计重写。nsh 没有的只有 `import.meta.hot` 这一面，语义按 Vite 的模块 API，没有自定义事件。测试步骤不比现在的 `@nlayer/test` 多。

三端同一语义。web 不把 QuickJS 打进 wasm：页面执行开发包，wasm 仍只跑 reactive 图、布局和 mount batch。

## 完成的标准

同一个 TSX 应用（`examples/gallery` 加一屏能看出状态留住）用 v6 的 `nlayer run` 在三端跑起来，并满足：

1. 保存改过的模块后，宿主进程不重启，web 不整页刷新。顶层 `signal()` 和 `createNavStack()` 在 initializer 代码没变时留住值，导航栈留在当前屏。`context()` 身份不变，provider 和 consumer 不断。改过签名的组件重渲染；没改的组件实例留着。
2. 不能自己接住更新的模块沿 importer 重跑到入口。`import.meta.hot.accept` 接住的停在这一层。
3. 编译失败不换正在跑的应用。终端打诊断，宿主上有遮罩。下一份成功的更新拿掉遮罩。
4. 补丁的 base 对不上、`accept` 回调抛错、或调用 `decline()`：同一进程加载整包，状态丢掉，终端打一行原因。不杀宿主，不重新安装。
5. 只有图片或其它资源字节变了、JS 没变：不重跑模块。已经画上的 `Image` 保持旧解码。新的加载看到新字节。
6. `nlayer build` 和 `nlayer package` 仍是单文件 ESM。`nlayer test` 仍是冷启动，不在测试中途推补丁。应用源码不能 `require`。发布包里 `import.meta.hot` 是 `undefined`。
7. 测试：无窗口断言完成标准里的留状态、冒泡、`accept` 停泡、`decline` 整包重载。三端各一条冒烟：第二次成功构建不重启进程。`nlayer test --target` 的现有步骤走这条 WebSocket，结果与换通道之前一致。不做设备像素断言。

`nlayer run` 没有 `--hot`。失败才整包重载。

## 产品面

### 开发包

只 `nlayer run` 使用。`preserveModules`，每个模块一个 factory，注册进 hot runtime。入口先装原生模块的命名空间，再跑。

发布包、`build`、`package`、`test` 仍是现在的单文件 ESM。factory 是开发包内部格式，不是应用能调用的 `require`。不提供 CJS 兼容层。

转换从 nsh 的 `hot.rs` 搬：

- 顶层、名字大写、函数体含 JSX 的函数，以及顶层 `mount()` 的函数参数，注册成稳定代理。签名含组件自己的代码，以及模块里组件以外的代码。签名变了，已挂实例重渲染。
- 顶层 `context()` 走身份保留。
- 顶层 `const` 的 `signal()` 和 `createNavStack()` 走 `keep`。initializer 代码变了就丢掉，重新建。
- 不 keep `resource()`、`createAnimatedValue()`、`computed()`、`effect()`。这些在模块重跑时重建。`storage` 是进程级单例，不进 `keep`。

`import.meta.hot` 由打包器在开发包里注入。应用不从 `@nlayer/runtime` 导入它。

### import.meta.hot

类型在 `packages/globals`，由 `gen-types` 生成，`import.meta.hot` 可选。发布包运行时是 `undefined`。没有 `on` / `off` / `send`。

| 成员 | 行为 |
|---|---|
| `accept()` / `accept(cb)` | 本模块重跑。`cb` 收到新的模块命名空间。importer 不重跑。 |
| `accept(dep, cb)` / `accept(deps, cb)` | 这些依赖更新时不重跑本模块，调用 `cb`，传入新命名空间。其它依赖仍冒泡。 |
| `dispose(cb)` | 本模块即将重跑时调用。`cb` 收到 `data`，写进去的值下一轮还能读。 |
| `prune(cb)` | 本模块不再在图里时调用，传入 `data`。 |
| `invalidate()` | 本模块当作没接住，沿 importer 冒泡。 |
| `decline()` | 同一进程整包重载，状态丢掉。 |
| `data` | 跨一轮更新的对象。第一轮是空对象。 |

`accept` 只决定冒泡停在哪。模块真的重跑时，组件代理、`context` 和 `keep` 仍按上一节生效。

`cb` 抛错按整包重载处理。

### 运行时

两份，语义相同：

- QuickJS：`nlayer-js`，从 `nsh-js/src/hot.rs` 搬，加上表里的 Vite 成员。
- web：页面里的脚本，从 `nsh-platform-web/web/browser/hot.js` 搬，加上同一批成员。

更新只重定义改过的模块，然后重跑它们，以及不能自接的 importer，直到入口或某个 `accept`。JS 上下文、没重跑的模块、原生视图留着。

模块重跑前先跑它的 `dispose`，再跑 nsh 那套 undo：这个模块上一次顶层做的、没有被 `keep` / 代理接住的事要撤掉。`mount()` 用同一个代理再次调用时留住已挂的树；从第一个不同的 `mount` 起，后面的拆掉重做。

### 通道

`nlayer-cli` 起开发服务器。三端连同一条 WebSocket。JSON 文本帧，补丁和整包是后续二进制帧。协议类型放在 `nlayer-engine`。`nlayer-cli` 为了序列化依赖它。不新增 crate。

消息：

- `Hello`：协议版本。测试会话的 hello 标明 `test`，宿主不盖开发遮罩，也不应用补丁。
- `Patch`：`version`、`base`。base 对得上的宿主执行后面的脚本。对不上的忽略补丁，等同一版本的 `Bundle`。只用于 `run`。
- `Bundle`：`version`，整份开发包。新连接先拿当前这份。
- `BuildFailed`：诊断文本。`run` 的宿主盖遮罩，不换应用。测试会话里编译失败直接让这次 `open` 失败，不盖遮罩。
- `Step`：一条现有测试步骤。宿主用自己的输入做完，再回一条结果。没有 nsh 的 `Scene` 全表。

不搬 `CannotRun`、capabilities、limits、`app_id`、菜单、剪贴板、`host.send`、对话框、keymap、拖文件、截图。源映射跟补丁和整包走，遮罩和终端用它定位。

Android 用 `adb reverse` 把端口转到设备，`run` 结束时只去掉这一条。iOS 模拟器连宿主机。web 连同一个端口。不再靠轮询 generation 来整页刷新。

编译失败仍只打终端加遮罩，不推补丁。上一份成功的开发包继续被新连接拿到。

资源文件仍由开发服务器按路径提供。字节变了不产生 `Patch`。

### 遮罩

宿主绘制，不是公开组件，也不是应用能挂的元素。编译失败时盖住应用，下一份成功更新拿掉。整包重载不经过这层遮罩；那是终端里的一行原因。

### 测试会话

`nlayer test` 无窗口仍直接调引擎，不连这台服务器。

`nlayer test --target web` 每次 `open` 起自己的测试会话。`nlayer test --target ios|android` 在同一次命令里留着宿主进程和那条套接字：第一次 `open` 启动进程并推开发包，之后的 `open` 先发 `recycle` 再推一份新的开发包。`recycle` 丢掉引擎和原生视图树，下一份包在同一个进程里启动新的 QuickJS。套接字断了才重新启动进程。两次 `open` 都不附着到用户正在跑的 `nlayer run`。会话推包之后只下发步骤。测试中途不推 `Patch`。`--target` 的宿主只装 factory 运行时，避免再留一套 ESM 加载器；这份包不热更新。无窗口和 `package` 仍是单文件 ESM。

步骤与现在的 `@nlayer/test` 一一对应：`texts`、`inputs`、`press`、`hover`、`focus`、`down`、`up`、`warnings`、`longPress`、`type`、`select`、`compose`、`scroll`、`drag`、`dragAndHold`、`drop`、`back`、`advance`、`waitFor`、`tree`、`selectionOwner`、`openedUrls`、`close`。选择器规则不变。iOS、Android 现在的 stdin 行 JSON 删掉，不留第二通道。

web 的指针、按键、滚动仍走浏览器真实输入。查询、等待和 `open` 的选项走套接字。不把事件灌进引擎。

### 替换 v1 的运行句

`nlayer run` 监视 TSX 和导入的资源。JS 变了推补丁；资源只变了换字节。编译失败留住上一份。补丁套不上才在同一进程重载整包。`package` 的产物不连这台服务器。`nlayer test --target` 用同一条套接字下发步骤，不热更新。iOS 和 Android 的测试在 `open` 之间用 `recycle` 丢掉 QuickJS 和组件树，不杀掉宿主进程。

## 开发计划

### M1 开发包

`nlayer-bundler`：`run` 和 `test --target` 走 `HotBundle` 和 hot 转换。`test --target` 只推一次，不热更新。无窗口 `test`、`build`、`package` 仍是单文件 ESM。注入 `import.meta.hot`，不把它变成应用可导入的模块。

单测：组件代理注册、`context`、`keep` 只包 `signal` 和 `createNavStack`、`mount()`、签名随组件外代码变。发布构建不含 factory，也不引用 hot runtime。

来源：`nsh-bundler/src/hot.rs`、`nsh-bundler/src/bundle.rs` 的 `HotBundle`。裁掉 nsh 的 UI set 和 capabilities。

### M2 QuickJS 运行时

`nlayer-js` 的 hot runtime。内部模块供开发包导入，应用源码写不了它的 specifier。Vite 那一表的成员在这里实现。`accept(dep)` 不重跑本模块。`decline` 和回调抛错向引擎要整包重载。

来源：`nsh-js/src/hot.rs`。Vite 成员是新代码，不发明第二套冒泡。

### M3 引擎

`EngineControl::hot_update`。套不上或运行时要求重载时，同一 JS 上下文加载整包，状态丢掉，原生宿主进程留着。无窗口测试覆盖完成标准 1、2、4 里不需要像素的部分。

来源：`nsh-engine` 的 `hot_update` 和 `nsh-engine/tests/engine/hot.rs`。不搬 shader、字体重复注册这些 nlayer 没有的路径。

### M4 通道

协议类型在 `nlayer-engine`。`nlayer-cli` 的开发服务器改成 WebSocket。监视仍是现在的轮询字节。成功且模块变了：先 `Patch` 再 `Bundle`。只有资源变了：换文件，不发 `Patch`。失败：`BuildFailed`，文件表留着上一份。

Android `adb reverse` 在 `run` 和 `test --target android` 里成对出现。iOS 不再为了一次 TSX 保存 `simctl` 重启。web 不再为了 generation 变化整页刷新。

来源：`nsh-dev/src/protocol.rs` 的 `Hello` / `Patch` / `Bundle` / `BuildFailed`，以及测试会话怎么把步骤送到宿主。`TestStep` 按上面的名单裁，不整段搬。`nsh-cli` 的推送和 `adb reverse` 照搬边界。

### M5 三端宿主

iOS、Android、web 连接、应用补丁、失败时整包重载、显示遮罩。web 的 hot runtime 从 `nsh-platform-web/web/browser/hot.js` 搬，语义对齐 M2。开发页执行 factory，不把应用当页面原生 ESM 加载。发布页不变。

冒烟：第二次成功构建后进程还在（web 是同一个文档）。遮罩在编译失败时出现，成功后消失。

### M6 测试通道

`nlayer test --target` 改走测试会话。步骤名与现在的 `HostedApp` 相同。iOS、Android 的 stdin 行 JSON 删除。web 的输入仍走 DevTools。现有 `--target` 测试保持绿，不改 `@nlayer/test` 的导出。

来源：`nsh-cli` 的 `test_host` 会话和 `DevServer::step`。不搬 `TestNetwork`、`TestSetup` 里 nlayer 没有的字段。`open` 已有的 viewport、safe area、keyboard、color scheme、`dataDir` 仍由这次会话在第一帧之前设上。

### 顺序

M1 先合。M2 依赖 M1 的注册约定。M3 依赖 M2。M4 的消息类型可以和 M2 并行，接入推送依赖 M3。M5 依赖 M3 和 M4。M6 依赖 M4，并依赖 M5 的宿主连接。web 的 JS runtime 可以在 M1 的约定稳定后和 M2 对照着写，接入页面依赖 M4。

## 不进 v6

| 项 | 为什么 |
|---|---|
| `hot.on` / `off` / `send` | 插件事件通道。不留扩展钩子 |
| 应用面 `WebSocket`、`crypto.subtle` | 仍是以后要做。开发服务器的套接字不是这套 API |
| nsh 测试协议的其余部分 | 菜单、剪贴板、`host.send`、对话框、keymap、拖文件、截图、`Scene` 全表、`TestNetwork`。步骤只覆盖现在的 `@nlayer/test` |
| 新 crate、`nlayer-dev` | 仓库 crate 名单不变 |
| 应用可调用的 `require` | 永久不做。factory 只在开发包内部 |
| `resource()`、`createAnimatedValue()` 的 `keep` | 只跟 nsh 的 keep 名单 |
| 已显示图片的热替换 | 资源更新不重跑模块，也不清宿主解码缓存 |
| `--hot` 开关 | `run` 默认就是。不留两套长期行为 |
| `nlayer test` 里的热更新、设备像素断言 | 测试的 QuickJS 和组件树仍冷启动。iOS、Android 复用宿主进程，不在一次 `open` 里推补丁 |
| 签名包、嵌入 ABI、`nlayer check`、桌面 | 永久不做或不预承诺 |

## 风险与决定

- **`run` 的契约变了。** v1 到 v5 保存后状态丢掉。v6 起默认留住。`package` 不变。`test` 的 QuickJS 仍冷启动。web 每次 `open` 一个会话；iOS、Android 在一次 `nlayer test --target` 里留着进程，`recycle` 之后才加载下一份包。`--target` 的通道是这条套接字。
- **开发包和发布包不是一种格式。** 只 `run` 用 factory。发布包继续单文件 ESM，避免把 CJS 兼容层带进产品。
- **web 开发执行方式变了。** 开发页跑 factory runtime，不再把 bundle 当原生 ESM。发布页仍是原生 ESM。两份 hot runtime 必须靠同一组行为测试对齐。
- **`import.meta.hot` 比 nsh 多。** 冒泡、代理、`keep` 仍是 nsh 的。`accept` 只增加停泡点。没有事件总线。
- **整包重载留在进程里。** 比现在的重启快，但 signal 和导航栈会丢。这是失败路径，不是成功路径。
- **遮罩不是 UI 组件。** 不进 `@nlayer/ui`，应用不能挂、不能样式化。
- **协议放在 `nlayer-engine`。** 宿主本来就依赖它。CLI 新增对它的依赖，为了序列化 HMR 消息和现有测试步骤。不为此加 crate。
- **资源不触发模块重跑。** 改一张图不会丢掉导航栈，也不会换掉已经画上的解码。
