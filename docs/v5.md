# v5

本文件是 0.5.0（v5）的产品范围和开发计划。v1、v2、v3、v4 的产品面与验收不变（`docs/v1.md`、`docs/v2.md`、`docs/v3.md`、`docs/v4.md`），只有一条例外：v1 写的「class 解析器为空，任何 class 警告且不生效」由本版替换。v5 只从 `AGENTS.md` 的「以后要做」里取 Tailwind utility 表。没列出的仍留在那一档。永久不做、不预承诺不因 v5 改变。

主题配置、design token、`dark:`、断点、`group`、兄弟位置、平台变体、`motion-*`、无障碍变体，以及宿主还不画的 utility，解析器要认得。它们不生效，并警告。不留配置入口，也不留注册钩子。这些仍是以后要做。语法已经收下，以后要生效只打开对应的门；本文件不写那个门以后怎么做。

## 目标

v4 让文字能被读完。v5 让已经会画、已经会排的样式能用 Tailwind 4 的 class 写出来。

解析器从 nsh 搬，基本完整：默认主题、任意值、`!`、变体语法、冲突顺序、整张 utility 表。没实现的功能仍能解析，警告，不写入样式。

实现照 `../nsh` 的 `nsh-core` tailwind 和 class 应用。不搬 Rust 的类型化样式方法（`.p_4()`），不搬 `nsh.json` 的 `"tailwind"`，不搬 design token。

## 完成的标准

同一个 TSX 应用（`examples/gallery` 加一屏 class）用 v5 的 CLI 在三端跑起来，并满足：

1. 无变体、且过了下面生效门的 utility 生效。至少包括：`flex`、`p-4`、`gap-3`、`bg-zinc-800`、`text-sm`、`font-semibold`、`rounded-lg`、`opacity-50`、`translate-x-1`、`object-cover`、`line-clamp-2`、`space-x-2`，以及任意值（`bg-[#7c3aed]`、`w-[37px]`）。数值是 Tailwind 4 默认主题，1rem = 16pt。
2. 状态 class 在引擎里重算，布局也算：`hover:p-4`、`active:scale-95`、`focus:`、`focus-visible:`、`focus-within:`、`disabled:`、`enabled:`。按下、悬停、聚焦由宿主上报。`disabled:` / `enabled:` 读元素已有的 `disabled`。`disabled` 时 `active:` 不生效，照 nsh。
3. 未实现的不写入，并警告。至少包括：`shadow-md`、`bg-linear-to-r`、`blur-md`、`ring`、`outline`、`animate-spin`、`transition`、`dark:bg-white`、`sm:flex`、`w-screen`、`portrait:`、`ios:`、`motion-reduce:`、`rtl:`、`group-hover:`、`first:`、`odd:`、`aria-selected:`、`placeholder:text-zinc-400`、`caret-red-500`。`selection:bg-*` 生效，三端已经画 `selectionColor`。
4. 一条 utility 里只要有一条声明过不了门，整条不写入。`p-4 shadow-md` 里 `p-4` 生效，`shadow-md` 警告。
5. 冲突照 nsh，不用 `tailwind-merge`。同一字符串后面的 class 赢。变体按 rank 排，不按出现位置。`classList` 在 `class` 之后。`!` 是 important。`style` 按 key 赢过 class。`activeStyle` / `hoverStyle` / `focusStyle` 仍是平台绘制覆盖，不改布局，并盖住同一绘制 key 的状态 class。
6. 警告两条。同一 class 字符串只报一次。不失败构建。表里没有：`unknown classes: wat`。解析了但不生效：`unsupported classes: shadow-md dark:p-4`。nsh 忽略、且不警告的名单照搬：`antialiased`、`subpixel-antialiased`、`isolation-auto`、`appearance-none`、`appearance-auto`、`will-change-*`。构建只检查静态 `class` 和 `classList` 的静态键；非静态片段不猜。
7. 动态 class 在运行时解析（`` class={`bg-${name}-500`} ``）。按字符串缓存，上限 4096，满了清空，照 nsh。
8. 测试：`nlayer test` 无窗口断言布局、颜色、状态重算和两条警告。三端各一条冒烟：这屏能打开，悬停和按下不崩。不做设备像素断言。
9. 打包：`nlayer package --target web|ios|android` 的产物仍能启动并跑这屏。不新增 crate，不新增公开模块，不改 `nlayer.json`。

`nlayer test` 默认无窗口。无窗口不模拟指针轨迹，只接受测试置上的按下、悬停、聚焦。`disabled` 用元素属性。

## 产品面

### 解析

从 nsh 拷 `tailwind`（`mod.rs`、`utilities.rs`、`theme.rs`、`palette.rs`）。拷的时候裁掉 `Theme::from_json`、`extend` 和 design token（`ClassTokens`）。引擎只用 `Theme::default()`。不导出主题替换，不读 `nlayer.json`。

变体语法、任意值、`!p-4` 与 `p-4!`、`group` / `group/name` 的切分都留下。`bg-brand`、`bg-(--primary)` 没有主题项，是 `unknown`，不是 unsupported。

`group` / `group/name` 自己没有声明。没有东西读它，记 unsupported。

### 生效门

一条已经解析出来的 class 写入样式，当且仅当下面三条都成立：

1. 每个变体都属于：无变体、`active`、`hover`、`focus`、`focus-visible`、`focus-within`、`disabled`、`enabled`。
2. 每条声明的样式 key，引擎已经拿去布局，或三端宿主都已经绘制。只在某一端有的不算。
3. 声明不依赖本版不跟踪的环境：窗口尺寸、明暗、平台、减弱动态、书写方向、`group`、兄弟位置、无障碍状态。

不过门的整条丢弃，名字进 `unsupported classes`。不写一半。

`space-x-*` / `space-y-*`（含 `-reverse`）是交给子节点的 margin，引擎能做，生效。`select-none` / `select-text` 走已经生效的 `userSelect`。`font-*` 只写成 `fontFamily` 字符串，和 `style` 一样，不加载字体文件。

已知过不了门、因此 unsupported 的族（表仍要能解析）：

- 阴影、内阴影、投影、文字阴影、渐变、`ring`、`outline`、filter、backdrop、blur、mask、blend
- `transition`、`animate-*`、`duration-*`、`ease-*`、`delay-*`
- 断点（`sm:`、`max-md:`、`min-[600px]:`）、`portrait:` / `landscape:`、`w-screen` / `h-screen` / `min-w-screen` 以及其他 `*-screen`
- `dark:`、`ios:`、`android:`、`web:`、`motion-safe:`、`motion-reduce:`、`rtl:`、`ltr:`
- `group`、`group-*`、`first:`、`last:`、`odd:`、`even:`、`only:`
- `selected:`、`checked:`、`indeterminate:`、`aria-*`、`data-*`
- `placeholder:`（宿主不画 `placeholderColor`）、`caret-*`（宿主不画 `caretColor`）

`selection:bg-*` 过门。它写 `selectionColor`，三端已经画。

### 状态

照 nsh 在引擎里重算。不把 class 塞进现有的三槽绘制。

- 宿主上报按下、悬停、聚焦。引擎自己维护 `focus-within`（自己或后代聚焦）。
- `disabled:` / `enabled:` 读元素的 `disabled`，不上报。
- `focus:` 和 `focus-visible:` 都看聚焦这一位，rank 不同，照 nsh。没有单独的键盘聚焦。
- 状态 class 可以改布局。`hover:p-4` 改 padding。
- 现有 `activeStyle` / `hoverStyle` / `focusStyle` 不动：仍是平台绘制覆盖，不改布局。同一绘制 key，覆盖盖住状态 class。`focusStyle` 仍是「自己或里面的输入聚焦」，不改成 Tailwind 的 `focus:`。

### 冲突

1. 同一字符串后面的赢。`"p-2 p-4"` 是 `p-4`。
2. 变体 class 按 rank 排，不看它写在字符串的哪里。
3. `classList` 在 `class` 之后。值为真才算。
4. `!` 写在 utility 前面或后面都是 important。
5. `style` 按 key 替换 class 写过的那个属性，其余留下。`style={{ paddingLeft: 8 }}` 替换 `pl-4`，留下 `pr-4`。

凡是今天已经接受 `class` / `classList` 的元素都走这套。不新增元素，也不新增属性。

### 警告

- `unknown classes: a b`：解析失败。表里没有、任意值不合法、或 nsh 也不认的变体。
- `unsupported classes: a b`：解析成功，生效门没过。
- 同一 class 字符串第一次解析时各报一次。缓存命中不报。
- 构建走同一个解析器。只看静态字符串和 `classList` 的静态键。模板里非静态的片段不猜。警告不失败构建。
- `nlayer-js` 和 web 协议不再自己按空白切词。警告从引擎已有的通道出去。

## 开发计划

### M1 解析器

`nlayer-core` 的 `tailwind`：从 `nsh-core/src/tailwind/` 裁进默认主题和 utility 表。生效门和两条警告加在解析结果上，不改 utility 表的算法。只用 `Theme::default()`。

单测：过门的 class 写出对应声明；unsupported 不写入；unknown 与 ignored 分开；`!` 和变体顺序；`selection:` 过门；`placeholder:` 不过。

来源：`nsh-core/src/tailwind/{mod,utilities,theme,palette}.rs`。

### M2 引擎应用

`class` / `classList` 进节点样式。状态重算：按下、悬停、聚焦、`focus-within`、`disabled`。`space-*` 写子节点 margin。`style` 按 key 盖住 class。无窗口可以置按下、悬停、聚焦。现有 `StateStyle` 绘制槽保留，仍不改布局。

来源：`nsh-core/src/core/classes.rs`，以及 `nsh-core/src/core/mod.rs` 里的 class 缓存和 `set_states`。裁掉 dark、窗口尺寸、`group`、兄弟位置的重算。

### M3 宿主上报

iOS、Android、web 把按下、悬停、聚焦报给引擎。照 nsh 的 `TrackStates`，只这几位。`activeStyle` / `hoverStyle` / `focusStyle` 的平台覆盖保持原样。

来源：三端里 nsh 上报交互状态的路径。不搬阴影和渐变的绘制。

### M4 构建检查

`nlayer-bundler` 的 class 检查改为调用核心解析器。静态的 unknown 和 unsupported 警告，不失败构建。动态片段跳过。

来源：`nsh-bundler/src/classes.rs`，接在现有 `nlayer-bundler/src/classes.rs` 上。

### M5 样例

`examples/gallery` 加一屏：一行用 class 排的卡片、一处 `hover:` 或 `active:` 改布局或缩放、一处 `disabled:`、一处故意的 `shadow-md`（警告、不画）。保留已有的屏。无窗口测试覆盖完成标准里能在无窗口断言的部分。三端各一条冒烟。

### 顺序

M1 先合。M2 依赖 M1。M4 只依赖 M1 的解析入口，可以和 M2 并行。M3 依赖 M2。M5 等 M3。

## 不进 v5

| 项 | 为什么 |
|---|---|
| `nlayer.json` 的 `"tailwind"`、design token、`bg-primary` | 0.5 只用默认主题。不留配置入口 |
| `dark:`、断点、`w-screen`、`portrait:`、平台变体、`motion-*`、`rtl:` / `ltr:` | 环境重算不在本版。语法留下，unsupported |
| `group` / `group-*`、`first:` / `last:` / `odd:` / `even:` / `only:` | 不跟踪 group 和兄弟位置 |
| `selected:`、`checked:`、`aria-*`、`data-*` | 无障碍状态不驱动 class。那些属性仍是 v2 的 |
| 阴影、渐变、filter、backdrop、ring、outline、动画、transition 的绘制 | 仍是以后要做或不预承诺。class 不把它们写进 IR |
| `placeholder:`、`caret-*` | 样式 IR 有字段，宿主不画 |
| Rust 类型化样式方法、`tailwind-merge` | 应用只写 TSX。冲突已经是后者赢 |
| 自定义字体加载 | 不预承诺。`font-*` 只是 `fontFamily` 字符串 |
| 设备像素断言 | 仍不做 |

## 风险与决定

- **以前不生效的 class 会开始生效。** `class="p-4"` 在 v1 到 v4 只警告。v5 起它有 padding。这是本版替换 v1 那一句的原因。
- **不写一半。** 一条 utility 混有过不了门的声明时，整条丢弃。避免阴影的颜色写进去、阴影本身丢掉。
- **状态 class 走引擎，状态样式槽走平台。** `hover:p-4` 改布局。`hoverStyle` 里的 `width` 仍然不改布局。同一背景色，`hoverStyle` 盖住 `hover:bg-*`。
- **`focusStyle` 不改语义。** class 的 `focus:` 是元素自己聚焦（照 nsh，输入会报）。`focusStyle` 仍包含里面的输入。两者不是同一个条件。
- **`focus-visible:` 没有单独的位。** 照 nsh，它和 `focus:` 都看聚焦，只是 rank 不同。
- **窗口尺寸整类推迟。** 断点和 `w-screen` 共用同一条依赖。本版两条都不生效，避免只做一半重算。
- **不留主题钩子。** `from_json` 和 token 替换不进核心。以后要主题再搬，不在 0.5 留一个没人调用的入口。
- **警告不失败构建。** 和 v1 一样。静态检查只覆盖写死的名字。
