# v10

本文件是 0.10.0（v10）的产品范围。v1 到 v9 的产品面不变，只有三条例外：Android 的 `NavPage` 头不再用系统 `Toolbar`；web 的 `NavHeader` 改用下面这套外观；`pointerEvents` 按 nsh 的四值决定谁接指针。v10 不从「以后要做」取其它项。没列出的仍留在原档。永久不做、不预承诺不因 v10 改变。

## 目标

Android 的系统 `Toolbar` 是 56dp、标题靠左。iOS 的栏是 44pt 内容行、标题在栏的几何中心。0.10.0 让 Android 用原生自定义视图画一条跟这套尺寸一致的栏，并让 web 的 `NavHeader` 用同一套外观。导航公开属性不变。iOS 仍是系统栏。同一版让 `pointerEvents` 按 nsh 决定谁接指针：宿主只认挂载后的四值，不在宿主里做 CSS 继承。

## 完成的标准

同一个 TSX 应用用 v10 的 CLI 在三端跑起来，并满足：

1. Android 每个 `NavPage` 在自己的页面里画这条栏，跟着页面转场走，不是一条跨页不动的系统栏。`headerVisible` 不为 `false` 时显示。内容行 44pt，上面是状态栏 inset。不透明时内容从栏下开始，回传高度是状态栏 inset 加上 44pt。`headerTransparent` 时栏仍盖在内容上，高度不把内容往下推；内容的顶 inset 含这条栏的高度，跟 iOS 一样。`headerVisible={false}` 不画栏，内容的顶 inset 回到安全区。
2. 标题在整栏的几何中心，画在左右列上面。字符串标题单行，尾部省略，最大宽度是栏宽减去左右各 16pt。`headerTitle` 替换字符串标题，同样居中；宽过整栏才被栏边裁掉，可以盖住左右按钮。左右各占栏宽的一半，内容裁在自己的一半里，不画进另一半。leading 从栏的起始边起 16pt，trailing 在结束边前 16pt。方向跟布局方向走。
3. 字号 17pt，semibold，系统字体。返回是 `←`，无障碍名称是 `"Back"`。返回在非根页、`headerBackVisible` 不为 `false`、且没有 `headerLeft` 时出现。`headerLeft` 替换返回。`headerRight` 在 trailing。这三个在 Android 仍是 header item，不是 web 的 `NavHeader` 子节点。
4. 不透明且没有 `headerStyle.backgroundColor` 时，内容行底部有 0.5pt 分割线。浅色线是 `#3C3C43`、透明度 29%；深色线是 `#545458`、透明度 60%。设了 `backgroundColor` 就没有线。浅色：背景 `#ffffff`，标题 `#000000`，按钮 `#007AFF`。深色：背景 `#000000`，标题 `#ffffff`，按钮 `#0A84FF`。深色跟 `platform.colorScheme`。`headerStyle` 覆盖背景、标题色、按钮色。`headerTransparent` 时背景透明、没有分割线；字和按钮保持上面的标题色和按钮色，不改成白色。
5. web 的 `NavHeader` 用同一套外观：内容行 44px，标题 17px semibold，左右各一半且裁切，水平 inset 16px，分割线 0.5px，颜色与第 4 条相同。v9 的 slate 色板和透明栏默认白字不再使用。栏的结构不变：仍由 `NavPage` 挂进 `header` 槽，`headerLeft` / `headerRight` / `headerTitle` 仍是组件子节点。
6. `setNavHeader` 仍只影响 web。Android 和 iOS 上这个函数什么都不做。Android 不挂 `NavHeader`。
7. 状态栏图标的深浅仍跟应用的 `colorScheme`，不跟单页的栏背景走。
8. 不做：改 iOS 系统栏、大标题、`headerBackTitle`、系统按钮、按页替换头组件、`Dialog` 的头。不把无窗口改成画出这条栏。无窗口测试继续断言 `screen.title`、`headerVisible`、`headerHeight`。web 外观在 web 播放器测试和 `nlayer test --target web` 上验。`pointerEvents` 在无窗口命中、web 播放器和 iOS / Android 的命中上验。
9. `pointerEvents` 是 `"auto" | "none" | "box-none" | "box-only"`，写在节点上，不继承。没写是 `"auto"`。其它值警告且不生效。宿主读的是挂载后的这四值，不读类，也不沿祖先现算。
10. 四值跟 nsh 的宿主一样。`"auto"`：自己和子节点都接。`"none"`：自己和子节点都不接，宿主不把这次手势交给这棵子树，父级滚动因此接得到。`"box-none"`：子节点接，自己不接，点在自己的空盒上穿透。`"box-only"`：只接自己的边框盒，子节点不接。命中区域是边框盒，含 padding 和 border，不含 margin。点在边框盒外时，不裁剪、画在盒外的子孙仍按自己的盒子接，盒子自己不接。press、长按、pan、滚动、文本选择、输入聚焦、`href`、hover、active 都跟这个命中走。`opacity: 0` 仍可命中。`visibility` 和 `display` 的现有行为不动。
11. Tailwind 只有 `pointer-events-none` 和 `pointer-events-auto`，含已经会重算的 `hover` / `active` / `focus` / `focus-visible` / `focus-within` / `disabled` / `enabled`。类按 nsh 归并后再挂载，不把 CSS 计算值原样交给宿主：一个 `none`（自己的类，或上面最近的 `none`）里面有 `pointer-events-auto` 时，这个 `none` 挂成 `box-none`，那个 `auto` 挂成 `auto`；已经被挂成 `none` 或 `box-only` 挡住的子树，下面的节点挂成 `auto`。`box-none` 和 `box-only` 不沿类继承，也没有对应的 class。样式里写了 `pointerEvents` 且不是 `"auto"` 时盖过类：写 `"none"` 就是宿主的 `none`，不因为子孙有 `auto` 改成 `box-none`。不加组件 prop，不加模块导出。
12. 导航离场和模态穿透可以临时改宿主上的这个四值。这段结束时写回该节点挂载的值，不能清空。

## 产品面

没有新的导航属性，也没有新的模块导出。新的公开样式是 `pointerEvents`：`auto` | `none` | `box-none` | `box-only`，挂载规则按第 9 到 12 条。

### 和 v9 的差别

v9 写的是：iOS / Android 仍是系统栏；web 默认栏浅色白底深字，透明时字和按钮默认白色。从这一版起，Android 用上面的原生栏替换 `Toolbar`。web 的 `NavHeader` 改为第 4 条的尺寸和颜色，透明时不再把字和按钮改成白色。iOS 系统栏的外观不变。

v5 把 `pointer-events-none` / `pointer-events-auto` 解析后丢掉。从这一版起这两条按第 11 条归并后生效。v8 排除的 `box-none` / `box-only` 从这一版起是样式值。
