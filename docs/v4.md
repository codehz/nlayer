# v4

本文件是 v4 的产品范围和开发计划。v1、v2、v3 的产品面与验收不变（`docs/v1.md`、`docs/v2.md`、`docs/v3.md`）。v4 只从 `AGENTS.md` 的「以后要做」里取下面列出的项：`Text` 的文本选择（含可选中 `View`）、行内视图、`href` 链接。没列出的仍留在那一档。永久不做、不预承诺不因 v4 改变。实现上必需的小接口（选择模型、`Command::OpenUrl`、无窗口里对「这段可选 / 这次打开」的记录）算在对应项里，不单列。

## 目标

v3 让应用有真实的结构。v4 让里面的文字能被读完：一段里选、跨段选、行内放视图和图片、点一段文字打开链接。

进 v4 的判断仍是 v2 那条：应用没有它就得自己搭一层原生代码，或三端行为不一致。段内 `onPress` 已经是字符命中（`TextLink`），不是本版的 `href`。

实现照 `../nsh` 的 iOS、Android 和 web。只搬它已经有的这三端做法，不在 v4 里新设计 nsh 没有的语义。桌面手势、`TextView`、`nsh-base` 的 `Link`、`openUrl` 的 capability grant 都不搬。

## 完成的标准

同一个 TSX 应用（`examples/gallery` 加一屏阅读）用 v4 的 CLI 在三端跑起来，并满足：

1. 单段选择：`userSelect: "text"` 的一段（含它的 span）里，长按选出一个词，平台手柄延伸，系统编辑菜单能复制和全选。高亮和手柄用 `selectionColor`，缺省是平台强调色。选择不出这段。
2. 跨段选择：`View selectable` 里的文本按阅读顺序连成一次选择；`userSelect: "none"` 的文本跳过；嵌套的 `selectable` 并进最外层。并排的文本复制时用制表符连接，其余用换行。`List` 里只覆盖当时挂载的行，回收掉的行离开选择。
3. 行内视图：`Text` 里带布局的子节点（`View`、`Image`，以及 `Scroll` / `Input` / `List` 这类同样有布局的元素）是附件：占一个占位、按自己的尺寸排、默认坐在基线上，`verticalAlign` 为 `baseline` / `text-top` / `text-bottom` / `middle`，行高到能放下它。它保留自己的 `onPress`。被 `numberOfLines` 或省略号切掉的附件不显示。复制不含附件。
4. 链接：`Text` 的 `href` 在短按后由平台打开，然后报这段已有的 `onPress`。无 grant，不新增 `openUrl()`。打不开的地址不打开，仍报 `onPress`，并在终端警告。
5. 手势：可选中文本上的长按只做选择，不报 `onLongPress`，松手不补 `onPress`，也不打开 `href`。不可选的文本保持 v2 的长按。短按仍是 `onPress`。
6. 测试：`nlayer test` 的无窗口模型断言可选标记、附件 frame、`href` 的打开与拒绝。手柄、放大镜和系统菜单只在 `--target` 上冒烟。不做设备像素断言（同 v1）。
7. 打包：`nlayer package --target web|ios|android` 的产物仍能启动并跑这屏阅读；不新增 crate。

`nlayer test` 默认无窗口；`nlayer test --target web|ios|android` 的输入仍按 v1 的规则走宿主。无窗口不模拟词边界、手柄和菜单（选择 UI 是平台的，nsh 的无窗口同样不覆盖这些帧）。

## 产品面

### 单段选择

`userSelect` 和 `selectionColor` 已在样式 IR 里。v4 让它们生效，不另起一套名字。

- `userSelect`：`"text"` 可选，`"none"` 不可选，`"auto"`（缺省）跟外层。外层都没写时，三端都不可选。web 不为「桌面浏览器默认可选」单做一套：nsh 那条挂在桌面 idiom 上，这里没有桌面后端。
- 选择留在一个文本块里（这段和它的 span）。附件不进被复制的字符串。
- iOS：不可编辑的 `UITextInteraction`（长按选词、放大镜、手柄、高亮、系统编辑菜单：Copy、Select All、Look Up、Translate、Share）。
- Android：长按选词，手柄延伸，浮动工具条是 Copy、Select all、Share。
- web：浏览器自己的选择、菜单和快捷键。根上仍是 `user-select: none`；`"text"` 的段和 `selectable` 的视图打开 `user-select: text`。

不可选的文本不装这套手势。

### 可选中 View

```tsx
<View selectable style={{ gap: 12, padding: 16 }}>
  <Text>从这里…</Text>
  <Text style={{ userSelect: "none" }}>标签</Text>
  <Text>…到这里。</Text>
</View>
```

- `selectable` 是 `View` 的属性，不是样式。视图自己不为选择画装饰，高亮画在各段文本上。
- 一段已经 `userSelect: "text"`、又不在任何 `selectable` 里时，按单段选择。进了 `selectable` 之后，由外层选，这段不再单独选。
- 嵌套的 `selectable` 是外层的一部分，自己的手势不开始。
- 复制：阅读顺序里并排的段用制表符接，其余用换行。
- iOS / Android 的跨段手势和词边界照 nsh（核心里的选择模型）。web 是浏览器的一次选择，不跑这份模型。
- 不搬 `TextView`。没有文档组件参加这次选择。

### 行内视图

```tsx
<Text style={{ fontSize: 16, lineHeight: 26 }}>
  {"Made with "}
  <Image src={logo} style={{ width: 18, height: 18 }} />
  {" · "}
  <View style={{ height: 18, paddingHorizontal: 7 }}>
    <Text>LIVE</Text>
  </View>
</Text>
```

- 文本块的子节点里，span 和原文照旧。带布局、且不是 overlay 的其它元素是附件，也包含嵌在 span 里的。v1 把这些子节点丢掉；v4 接上。
- 每个附件是自己的布局根，按内容尺寸测量，再把尺寸交回文本测量。占位是一个对象替换符。`verticalAlign` 已在样式 IR 里。
- 附件的原生视图挂在这段文本下面，位置跟最终排版，不进 Taffy 的普通子节点流。
- 被截断隐藏的附件不占命中。复制跳过它们。
- 不把集合缩成只有 `View` 和 `Image`。`Input`、`Scroll`、`List` 放进文本时照 nsh 当附件，焦点和滚动仍是它们自己的。

### href

```tsx
<Text style={{ fontSize: 15 }}>
  {"By continuing you agree to the "}
  <Text href="https://example.com/terms" style={{ textDecorationLine: "underline" }}>
    Terms of service
  </Text>
  .
</Text>
```

- `href` 是 `Text` 的属性（块或 span），字符串。不新增组件，不搬 `nsh-base` 的 `Link`，也没有 `openWith`。
- 短按：取命中处最内层带 `href` 的 `Text`。地址通过 `check_url` 就打开，然后报这次按压已经会报的 `onPress`（span 或这段）。打不开则不打开，`onPress` 照旧，终端警告原因。
- `check_url` 照 nsh，去掉 grant：绝对 URL、最长 16 KiB、无空白或控制字符；拒绝 `javascript:`、`vbscript:`、`data:`、`blob:`、`file:`、`about:`、`asset:`；`http:` / `https:` 必须有 host。相对地址和 `#anchor` 不是绝对 URL，不打开。
- 打开是单向的。不把「打开了没有」报回 JS，不新增 `onOpenUrl`。web 弹窗被拦时同样没有回调。
- 平台：iOS `UIApplication.open`，Android `Intent.ACTION_VIEW`，web `window.open(url, "_blank")`。不经嵌入方的 URL 处理（没有嵌入 ABI）。
- 选择手势进行时不打开。`href` 不改变命中：段内 `onPress` 仍按现在的 `TextLink`。

## 公开模块

不变：只有 `@nlayer/runtime` 和 `@nlayer/ui` 两个原生模块，互不重导出。`@nlayer/runtime` 不增加 `openUrl`。

`@nlayer/ui`：`Text` 增加 `href`；`View` 增加 `selectable`。`userSelect`、`selectionColor`、`verticalAlign` 从「解析了但不生效」变成三端生效。不新增剪贴板 API；复制只走系统菜单。

类型仍由 `nlayer-bundler` 的 `gen-types` 生成到 `packages/`。

## 开发计划

每个里程碑是一个能合的切片：行为能跑，测试是绿的，没有空实现。改动到的 crate 跑 `cargo test -p`；动到 TSX、引擎或宿主的切片还要 `nlayer test` 绿。

### M1 文本协议与测量

- `nlayer-core`：`userSelect` 继承进 `AttributedText.selectable`；`selectionColor` 进段；`View` 的 `selectable`；`Text` 的 `href`。`set_inline` 对非文本保留布局节点。附件收集照 `update_attachments` / `collect_text`：布局根、占位、`verticalAlign`、截断隐藏。
- 选择模型：`selection.rs` 原样搬进 `nlayer-core`（词边界、阅读顺序、手柄、复制时的制表符和换行）。无窗口不跑手势，只保存标记。
- `Command::OpenUrl`：单向。`check_url` 从 `open_url.rs` 裁，不搬 grant、`not_granted`、嵌入方先处理、`EventKind::OpenUrl`。
- 测试：继承与 `"auto"` 的缺省不可选；附件 frame 与截断；合法 `href` 产生打开命令，拒绝的 scheme 不产生。

来源：`nsh-core/src/selection.rs` 1196、`nsh-core/src/open_url.rs` 的 `check_url`（约 16–54 行）、`nsh-core/src/core/mod.rs` 的 `collect_text` / `update_attachments`（约 5479–5653）、`nsh-core/src/text.rs` 的 `TextAttachment`。

### M2 iOS

- 单段：`text_selection.rs` 裁到不可编辑的 `UITextInteraction`。已有的按压识别器在选择开始时取消，不报 `onLongPress` / `onPress`。
- 跨段：`selectable_view.rs`。外层存在时，内层文本不再单独选。
- `href`：短按发出 `Command::OpenUrl`，由 `UIApplication.open` 执行。
- 测试：模拟器上长按选词、跨两段、点 `href` 不把测试进程导航走（打开命令在无窗口已经钉住；模拟器只冒烟手势和菜单出现）。

来源：`nsh-platform-ios/src/text_selection.rs` 686、`nsh-platform-ios/src/selectable_view.rs` 1089。

### M3 Android

- `TextBox` 的单段选择（长按、手柄、浮动工具条）和 `SelectableView` 的跨段选择。跨段的词边界与复制走 M1 的模型，经 JNI，不在 Java 再写一份。
- 选择开始时取消按压，避免 nsh 里两个长按计时器都触发。这是相对 nsh Android 的收紧，见「风险与决定」。
- `href`：`Intent.ACTION_VIEW`。
- 测试：同 M2 的模拟器冒烟。

来源：`nsh-platform-android/java/.../TextBox.java` 766（选择段）、`SelectableView.java` 558、`nsh-platform-android/src/selectable_view.rs`。

### M4 web

- 根保持 `user-select: none`。`"text"` 与 `selectable` 打开选择和系统菜单；`"none"` 在 `selectable` 里面也关掉。不搬 `.nsh-desktop .nsh-autoselect`。
- 跨段选择是浏览器的，不跑 M1 的模型。复制是浏览器的。
- `href`：`window.open(url, "_blank")`。被拦或不被拦都不回 JS。
- 行内附件是这段文本里的绝对定位子节点，坐标来自排版。
- 测试：无头浏览器里可选样式类、附件位置、短按发出打开（不要求新标签真的留下）。

来源：`nsh-platform-web/web/nsh.js` 的 `user-select` 段（约 116–218）和 `openUrl`（约 4573–4584）。

### M5 阅读屏

- `examples/gallery` 加一屏：可选的几段、一段 `userSelect: "none"`、一处行内图片和视图、一处 `href`。保留 v2 / v3 的屏。
- 无窗口测试覆盖完成标准里的可移植部分。三端各一条冒烟：这屏能打开，长按不崩。不在冒烟里跟随外链。

### 顺序

M1 先合。M2、M3、M4 只依赖 M1，可以并行。M5 等三端都绿。

## 不进 v4

| 项 | 为什么 |
|---|---|
| `TextView`、Markdown / HTML 文档 | `nsh-base`，不搬 |
| `Link`、`openWith`、`openUrl()` | `#[component]` 与 capability grant 都是永久不做。打开只从 `Text href` 走 |
| 剪贴板的 JS API | 复制是系统菜单，不新做模块 |
| 桌面选择（双击选词、三击选段、Shift+click、原生的 Cmd/Ctrl+A） | 没有桌面后端。web 上这些是浏览器的，不是本版的 API |
| web 上 `userSelect: "auto"` 默认可选 | 那是 nsh 的桌面 idiom，这里三端缺省都不可选 |
| `onOpenUrl`、打开结果 | nsh 的 `Link` 也不把系统结果交回应用的 `onPress`；本版连这个事件都不设 |
| SVG、GIF | 仍是以后要做 |
| Canvas、Video、WebView、TabBar、Tailwind、阴影与渐变 | 不在本版的「以后要做」取出项里 |
| 设备像素对齐断言 | 仍不做 |

## 风险与决定

- **长按只做一件事**：可选中文本的长按开始选择，并取消这次按压。不报 `onLongPress`，不补 `onPress`，不打开 `href`。v2 已经规定一次手势不能既长按又短按。nsh 的 Android 是两个等长的计时器，可能两个都响；v4 不照那个竞态。
- **`href` 没有 grant**：`fetch` 已经任意 URL。打开外链用同一条，不把 nsh 的 `openUrl` capability 搬回来。拒绝表只保留 `check_url` 里防代码和本地文件的 scheme。
- **不回传打开结果**：应用用 `onPress` 知道用户点了。系统没打开（没有应用接 `mailto:`、web 弹窗被拦）时界面无变化，也不抛错。
- **行内不缩范围**：任何有布局的元素都能进文本。`Input` 的焦点、`Scroll` / `List` 的滚动因此出现在一行里。这是 nsh 的行为；收成只有 `View` 和 `Image` 会是新设计。
- **选择模型只用在原生跨段**：web 用浏览器选择，单段 iOS 用 `UITextInteraction`。模型不要在 web 上再驱动一遍，否则一次拖动有两个高亮。
- **无窗口的保真度**：断言标记、附件几何和打开命令。不断言词的边界、手柄坐标和菜单文案。
- **`"auto"` 三端一致**：不为 web 检测「像桌面」再默认可选。要可选就写 `"text"` 或包进 `selectable`。
- **已有的 span 命中不动**：`href` 加在现有 `TextLink` 的短按之后，不改测试用来点 span 的规则。
