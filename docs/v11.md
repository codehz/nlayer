# v11

本文件是 0.11.0（v11）的产品范围和开发计划。v1 到 v10 的产品面不变，只有一条例外：`NavPage` 的头不再用 nsh / react-navigation 那套属性，改为 `UINavigationItem` 的核心。v11 不从「以后要做」取其它项。没列出的仍留在原档。永久不做、不预承诺不因 v11 改变。

## 目标

头的公开语义跟 `UINavigationItem` / `UINavigationBar`，不再跟 nsh。iOS 继续用系统 `UINavigationBar`（转场仍是 `UINavigationController`）。Android 和 web 已经是自绘栏，按同一份 item 模型排，颜色和尺寸对齐到能静态画出来的程度：不画系统模糊，不做大标题折叠，不跟滚动切 scroll-edge。

栈、模态、返回手势、`popOnBack` / `popOnSwipe` / `onBackPress` / `onDismiss` 不动。`Dialog` 没有这套头。

## 完成的标准

同一个 TSX 应用用 v11 的 CLI 在三端跑起来，并满足：

1. `NavPage` 不再接受 `headerLeft`、`headerRight`、`headerTitle`、`headerBackVisible`、`headerTransparent`、`headerStyle`。写了是不认识的属性：警告，不进树，不映射。`headerVisible` 留下。`NavHeader` 和 `setNavHeader` 从 `@nlayer/ui` 删掉。
2. 多个 leading / trailing。每一项是纯按钮或一个自定义视图。下标 0 靠屏幕外缘，跟 `leftBarButtonItems` / `rightBarButtonItems` 一样。
3. 返回按钮按 UIKit 拆所有权。被盖住的页写 `backButtonTitle` 和 `backButtonDisplayMode`。当前页写 `hidesBackButton` 和 `leftItemsSupplementBackButton`。没有自定义返回视图：要换掉系统返回就藏掉它，再自己放 leading。
4. iOS 上这些属性进当前页或下一页的 `UINavigationItem`，栏的折叠、材质、scroll-edge 由系统做。Android / web 用自绘栏画出下面「自绘栏」一节，不调用系统 `Toolbar`。
5. 大标题：iOS 在有页面使用 `always` 或 `automatic` 时打开 `prefersLargeTitles`，折叠是系统的。Android / web 只在 `always` 时多画一行静态大标题，不跟滚动收起；`automatic` 和 `never` 只画普通栏。
6. `scrollEdgeAppearance` 只在 iOS 跟系统滚动切换。Android / web 忽略它，只画 `standardAppearance`。不警告。
7. 没写 appearance 时：iOS 不覆盖 `UINavigationBarAppearance`。Android / web 用 v10 的不透明白/黑、分割线、17pt semibold 标题、按钮蓝。写了的颜色三端一起覆盖。
8. 旧的 gallery 和测试改到新接口。无窗口不断言像素，断言 title、按钮、返回模式、`headerVisible`、`headerHeight`。外观在 iOS 模拟器、Android 模拟器和 web 播放器上验。

## 产品面

```tsx
<NavPage
  title="Inbox"
  titleView={<Logo />}
  largeTitleDisplayMode="always"
  backButtonTitle="Inbox"
  backButtonDisplayMode="minimal"
  hidesBackButton={false}
  leftItemsSupplementBackButton={false}
  leading={[
    { title: "Edit", onPress: edit },
    <Filter />,
  ]}
  trailing={[{ image: icon, onPress: add }]}
  standardAppearance={{ backgroundColor: "#fff", titleColor: "#000", tintColor: "#007AFF" }}
  scrollEdgeAppearance={{ backgroundColor: "transparent", shadowColor: "none" }}
>
  {children}
</NavPage>
```

`leading` / `trailing` 的元素是下面两个形状之一，不能同时带 `title` / `image` 和子视图：

- 纯按钮：`title?`、`image?`（和 `Image` 的 `source` 同一份）、`onPress?`、`enabled?`（默认 true）、`tintColor?`。`title` 和 `image` 至少有一个，否则警告并丢掉这一项。
- 自定义视图：一个 nlayer 节点。视图自己画，不套按钮的 tint。按下由视图自己处理。

纯按钮的 `onPress` 不是返回。返回仍走引擎 back：先 `onBackPress`，再看 `popOnBack`。

### 属性

都是响应式的。

| 属性 | 写在哪一页 | 默认 | 作用 |
| --- | --- | --- | --- |
| `title` | 当前页 | 无 | 栏标题，也是盖住它的那一页在 `default` 模式下的返回文字 |
| `titleView` | 当前页 | 无 | 替换字符串标题。有它则不画大标题 |
| `largeTitleDisplayMode` | 当前页 | `"never"` | `"automatic"` / `"always"` / `"never"` |
| `backButtonTitle` | 被盖住的页 | 无 | 盖住它之后，返回按钮的文字。不设则用 `title` |
| `backButtonDisplayMode` | 被盖住的页 | `"default"` | `"default"` / `"generic"` / `"minimal"` |
| `hidesBackButton` | 当前页 | false | 藏系统返回。根页本来就没有返回 |
| `leftItemsSupplementBackButton` | 当前页 | false | true 时 leading 排在返回内侧；false 时有 leading 就替换返回（UIKit 的默认） |
| `leading` / `trailing` | 当前页 | 无 | 按钮或视图的数组 |
| `standardAppearance` | 当前页 | 无 | 见下 |
| `scrollEdgeAppearance` | 当前页 | 无 | 只影响 iOS |
| `headerVisible` | 当前页 | true | false 时不画栏。iOS 藏 `UINavigationBar`。内容顶 inset 回到安全区 |

`standardAppearance` / `scrollEdgeAppearance`：

- `backgroundColor?`：不写则这一项不覆盖平台默认。`"transparent"` 或 alpha 为 0：栏盖在内容上，顶 inset 含栏高（和现在的透明栏一样）。其它颜色：不透明，内容从栏下开始。
- `titleColor?`、`largeTitleColor?`、`tintColor?`。
- `shadowColor?`：不写则不覆盖。`"none"` 去掉分割线 / 系统阴影。颜色值则用这条线。

iOS 把写了的字段配进 `UINavigationBarAppearance`（不透明色用 opaque，透明用 transparent），没写的字段留给系统。Android / web 只读 `standardAppearance`。

导航其余属性不变：`animation`、`popOnSwipe`、`popOnBack`、`onBackPress`、`onDismiss`、`onInsets`、`style` / `class`。

### 自绘栏（Android / web）

栏在页面里，跟着转场走。内容行 44pt，上面是状态栏 inset。方向跟布局走。

没写 `standardAppearance` 时沿用 v10 的默认色：浅色白底、黑标题、`#007AFF` 按钮；深色黑底、白标题、`#0A84FF` 按钮。深色跟 `platform.colorScheme`。不透明且没有自定义 `backgroundColor` 时，底部分割线 0.5pt（浅色 `#3C3C43` 29%，深色 `#545458` 60%）。写了 `backgroundColor` 就没有这根默认线，除非 `shadowColor` 给了颜色。

标题在整栏几何中心，17pt semibold，单行，尾部省略。左右按钮按内容宽度从外向内排，间距 8pt，外缘距栏边 16pt。标题让开按钮，不再用 v10 的左右各半栏裁切。`titleView` 居中，宽过剩余空间才被栏边裁掉。

返回在非根页、当前页没有把返回替换掉时出现。显示模式读**下面那一页**：

- `default`：chevron 加下面那一页的 `backButtonTitle`，没有则用它的 `title`。文字空则只有 chevron。
- `generic`：chevron 加 `"Back"`。不本地化。iOS 的 generic 仍是系统本地化的 Back，这一处两端可以不一致。
- `minimal`：只有 chevron。

chevron 仍是 v10 那条路径（`M15 18 9 12 15 6`，24 视口，线宽 2）。文字 17pt regular，颜色跟 tint。无障碍名称是可见文字；只有 chevron 时是 `"Back"`。按下态沿用 v10：Android 圆形波纹，web 不透明度 0.3。

`leftItemsSupplementBackButton` 为 false 且 `leading` 非空：不画返回，只画 leading。为 true：返回在外，leading 在内。`hidesBackButton` 为 true：不画返回。

`largeTitleDisplayMode="always"` 且没有 `titleView`：内容行里不画居中标题，下面再加一行 52pt，大标题 34pt bold，距起始边 16pt，单行尾部省略。这一行算进栏高，不透明时把内容往下推。不跟滚动收起。`automatic` 在这两端等于 `never`。

`headerVisible={false}` 不画栏。完全自己画头用这个。

### 不做

- `UISearchController`、`prompt`、`UIBarButtonSystemItem`。
- 按页替换整个头组件。`setNavHeader` 不留。
- iOS 改成自绘栏。Android / web 不做大标题折叠、不做模糊、不自动切 scroll-edge。
- 每页 `statusBar`。状态栏图标仍跟应用的 `colorScheme`。
- `Dialog` 的头。
- 旧属性的兼容映射。

### 和 v10 的差别

v10 的导航公开属性是 nsh 那套，Android / web 用左右各半栏加一个返回 chevron。从这一版起属性换成上面的 item 模型；自绘栏按按钮内容宽度排，并按显示模式画返回文字。iOS 仍是系统栏，但开始把大标题、返回显示模式和两套 appearance 交给系统。v10 的默认色只还存在于 Android / web 没写 appearance 的时候。

## 公开模块

仍只有 `@nlayer/runtime` 和 `@nlayer/ui`。`@nlayer/ui` 去掉 `NavHeader` 和 `setNavHeader`。`NavPage` 的属性按上面的表换。类型仍由 `gen-types` 生成。

## 开发计划

每个里程碑是一个能合的切片。改到的 crate 跑 `cargo test -p`。动到 TSX、引擎或宿主的切片还要 `nlayer test` 绿。

### M1 协议和 JS

删掉旧的 screen header 属性（`headerLeft` / `headerRight` / `headerTitle` / `headerBackVisible` / `headerTransparent` / `headerStyle`）在 core、engine、js、web 协议里的字段。换成 item 数组、返回模式、两套 appearance、`largeTitleDisplayMode`。JS 的 `NavPage` 按所有权组包：返回标题和显示模式跟着这一页，供盖住它的页读。不认识的旧名字只警告。

无窗口模型记下这些字段和栏高（普通栏、透明、`always` 大标题、`headerVisible={false}`），不断言像素。

### M2 iOS

`UINavigationItem`：`title`、`titleView`（自定义视图进 `UIView`）、`leftBarButtonItems` / `rightBarButtonItems`（纯按钮用 title/image，自定义视图用 `customView`）、`hidesBackButton`、`leftItemsSupplementBackButton`、`backButtonTitle`、`backButtonDisplayMode`、`largeTitleDisplayMode`。有页需要大标题时 `prefersLargeTitles = true`。appearance 只覆盖写了的字段。`scrollEdgeAppearance` 交给系统跟滚动切换。不自绘。

### M3 Android 自绘

按「自绘栏」排多个按钮、返回文字、静态大标题和 `standardAppearance`。忽略 `scrollEdgeAppearance`。栏仍在每页里面，跟着转场。inset 规则按背景是否透明。

### M4 web

删掉 `NavHeader`、`setNavHeader` 和 header 槽里的默认组件。web 的栏改由宿主按同一套自绘规则画，不再是一个可替换的 JS 组件。历史返回和 `onBack` 的路径不变。

### M5 验收

`examples/gallery` 和现有导航测试改到新属性。三端各一条：多个 leading / trailing、补充或替换返回、三种显示模式、透明 `standardAppearance`、iOS 的 scroll-edge 与大标题折叠、Android / web 的静态大标题。
