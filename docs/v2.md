# v2

本文件是 v2 的产品范围和开发计划。v1 的产品面与验收不变（`docs/v1.md`）。
v2 只从 `AGENTS.md` 的「以后要做」里取下面列出的项；没列出的仍留在那一档。永久不做、不预承诺不因 v2 改变。实现上必需的小接口（`List` 的 ref 句柄、`AbortSignal` 取消、`nlayer.json`）算在对应项里，不单列。

## 目标

v1 证明同一个 TSX 应用能在 web、iOS、Android 上跑同一条路径。v2 让一个真实应用能写出来、发出去：长列表、动效、异步数据与本地持久化、深色与无障碍、多行输入和中文 IME、系统返回，以及一个不签名的安装包。

进 v2 的判断只有一条：应用没有它就得自己搭一层原生代码，或者三端行为不一致。

## 完成的标准

同一个 TSX 应用（`examples/gallery`，v2 加屏）用 v2 的 CLI 在三端跑起来，并满足：

1. 列表：5000 行，复用，`header` / `footer` / `empty` / `separator`，`numColumns`，估算加实测行高，`onLoadMore` 每次接近末端只触发一次，`scrollToIndex` / `scrollToEnd`，滚动事件照旧。
2. 动效：`timing` 和 `spring` 驱动 `opacity`、`backgroundColor`、`borderColor`、`transform` 的 translate / rotate / scale；`interpolate` 派生数值和颜色；`finished` 在结束时兑现；长按触发。无窗口测试用确定性时钟断言中间值和结束值。
3. 数据：`resource` 的加载、错误、`refetch`、取消；`storage` 在 iOS / Android 进程重启后读回，web 刷新后读回；5 MiB 配额。
4. 适配：`platform.colorScheme` 随系统切换，样式跟着重算；`role` / `accessibilityLabel` / 状态在 VoiceOver、TalkBack、ARIA 上可读；`disabled` 挡住按压。
5. 输入：`multiline` 的 Return 换行；`selectedRange` 受控；拼音输入法的 `onCompositionChange` 往返，受控值不打断输入。
6. 返回：Android 的返回键和返回手势、web 的后退（应用自己推了历史条目）触发 `BackHandler`；iOS 没有系统返回，不触发。
7. 打包：`nlayer package --target web|ios|android` 产出静态站、APK、未签名 `.app`，产物离开 CLI 能装能跑。

`nlayer test` 默认无窗口，`nlayer test --target web|ios|android` 用宿主自己的输入。不做设备像素断言（同 v1）。

## 产品面

### 列表

`List` 是自带滚动视图的宿主组件。它不新增原生视图类型：一个 list 就是一个 `Scroll`，cell 是普通 `View`，平台只应用 frame、内容尺寸和滚动偏移。窗口、行高、回收和滚动命令都在核心里算。

```tsx
<List
  each={rows()}
  estimatedItemSize={56}
  keyExtractor={(row, i) => row.id}
  header={<Header />}
  footer={<Footer />}
  empty={<Empty />}
  separator={<Divider />}
  onLoadMore={() => loadMore()}
  ref={list}
  style={{ flex: 1 }}
>
  {(item, index) => <Row title={item().title} index={index()} />}
</List>
```

- 行函数按 cell 调用，不按 item 调用；cell 会被复用，`item()` / `index()` 跟着变。行里读位置要在用到的地方读，不许在函数顶部把值拷出来（同 nsh 的规则）。
- `estimatedItemSize` 默认 50 point；行测出来后回填前缀和。`numColumns` 默认 1。`keyExtractor` 默认 `item.key`、`item.id`，都没有就用下标。
- `header` / `footer` / `empty` / `separator` 随内容滚动；`empty` 只在 `each` 为空时显示。
- `onLoadMore` 在视口进入 `loadMoreThreshold`（默认 1）个视口时触发，每次 item 数量只触发一次；打开时第一页不足也会触发一次。没有 `onLoadMoreAtStart`。
- `ref` 给一个 `List` 句柄：`scrollToIndex(index, { animated })`、`scrollToEnd({ animated })`。行还没真正排过时按估算尺寸定位，随后按实测尺寸跟随。v2 不给其它宿主 ref。
- `initialScrollIndex` 在第一帧前定位。
- `onScroll` / `onScrollEnd` / `onScrollDragStart` / `onScrollDragEnd` / `onMomentumStart` / `onMomentumEnd` 与 `Scroll` 相同；`testID`、无障碍属性和 `style` 也照 `Scroll`。
- cell 是各自的布局根：一行变化不重排整页。内容尺寸来自列表记账，不是 Taffy 溢出。
- 滚动偏移同时进核心（窗口、回收、滚动命令）和 JS（`onScroll`）。核心自己发过的 `ScrollTo` / `ScrollBy` 按已发数量重放，平台回报不会把它算成用户滚动。
- 绑定分帧：视口内的 cell 在当次提交里绑好，overscan 在后续帧按预算绑（每轮最多 150 个 op 或 2 ms，至少一个 cell），绑定中显示的 cell 先藏起来。

v2 不做：sticky header、`inverted`、`maintainVisibleContentPosition`、`viewport="parent"`、`onViewableItemsChange`、下拉刷新、分页、吸附、缩放、横向列表。这些各有自己的平台工作，见「不进 v2」。

### 动效

```ts
const v = createAnimatedValue(0);
const opacity = v.interpolate({ inputRange: [0, 1], outputRange: [0.4, 1] });
v.timing({ toValue: 1, duration: 300, easing: "ease-out" }); // Promise<{ finished }>
v.spring({ toValue: 1, stiffness: 180, damping: 20, mass: 1, velocity: 0 });
// `Animated.timing(v, …)` / `Animated.spring(v, …)` 同义
```

- 值与节点是 JS 描述的图：`createAnimatedValue`，值上的 `interpolate`（数值、颜色，`extrapolate` 为 `clamp` 默认 / `extend`）、`timing`、`spring`；`Animated` 上的同名函数是另一种写法。JS 不逐帧运行。
- `easing` 是数据：`linear`、`ease`、`ease-in`、`ease-out`、`ease-in-out`、`cubic-bezier(x1, y1, x2, y2)`、`steps(n, position)`。不接函数。
- 可绑定的属性：`opacity`、`backgroundColor`、`borderColor`（四边同色）、`transform` 里的 translate / rotate / scale 步骤。样式里写值本身，不写包装对象。
- 停止：`v.stop()` 停在当前值；值被 GC 回收时绑定释放，进行中的动画以 `{ finished: false }` 结束。
- 图在宿主线程上跑：iOS 主线程（`CADisplayLink`）、Android UI 线程（`Choreographer`）、web 页面主线程（`requestAnimationFrame`）、无窗口测试的引擎线程（测试时钟）。引擎线程只发动画 op、收 `finished` 和 `get()` 的答复，不逐帧跑图。
- 长按：`onLongPress` + `delayLongPress`（默认 500 ms）。到时长按触发，松手不再补 `onPress`；拖动或滚动先成立则整个按压取消。已有 `onPress` 的短按语义不变。

v2 不做：`decay`、`Animated.sequence` / `parallel` / `loop` / `stagger`、keyframes / motion 预设、布局动画、样式过渡、`scrollValue` / `pullValue`、pan / pinch / rotation 手势、文本颜色绑定、canvas / 原生组件槽位、reduced motion 开关（低层动画按写好的播放）。

### 数据

`resource`（`@nlayer/runtime`）：

```ts
const user = resource(fetchUser);                     // 加载
const userById = resource(() => id(), (id, { signal }) => fetchUser(id, { signal })); // 源变化时重载
user();          // T | undefined
user.state();    // "unresolved" | "pending" | "ready" | "refreshing" | "errored"
user.error();    // unknown
user.loading();  // boolean
user.refetch();
user.mutate(value);
```

- 源为假值时不加载，状态 `unresolved`。
- fetcher 在 `untracked` 里调用，拿到 `{ signal, refetching }`；重跑、释放、被新一次加载取代都会 abort 上一个 signal。
- fetcher 抛错或 reject 进 `error()`，状态 `errored`，上一个值保留，不向外抛。源本身抛错仍按渲染错误进最近的 `ErrorBoundary`。
- `fetch` 的取消要真取消：引擎的网络请求按 `AbortSignal` 结束，不只把 promise 拒掉。

`storage`（`@nlayer/runtime`）：`getItem(key)`、`setItem(key, value)`、`removeItem(key)`、`keys()`、`clear()`，都是 `Promise`，键和值都是字符串。上限 5 MiB（键加值的 UTF-8 字节），超了 reject 一个 `name` 为 `QuotaExceededError`、`code` 为 `ERR_NLAYER_QUOTA_EXCEEDED` 的 `Error`，旧值不动。存储是应用私有的，不经 grant。

后端：iOS 是 Application Support 下的文件，Android 是 `getFilesDir()` 下的文件，web 是 `localStorage`（前缀取 `nlayer.json` 的 `id`，没有就用页面路径），无窗口测试是内存（`open` 可以给一个临时目录）。文件后端整份 JSON 重写，先写临时文件再改名。

v2 不做：WebSocket、cookie、`crypto.subtle`、流式 fetch。

### 适配

- `platform.colorScheme: () => "light" | "dark"`。系统变化时它变，读它的样式、effect 重算。没有 `setColorScheme`，没有 `dark:` class，也没有自适应颜色 token：主题由应用自己算。
- 根界面跟随：web 页面的 `color-scheme`、`<html>` 背景，iOS 根视图背景，Android 窗口背景和状态栏图标明暗。
- 无障碍属性（所有宿主）：`role`、`accessibilityLabel`、`accessibilityHint`、`accessibilityElementsHidden`、`accessibilityState`（`disabled` / `selected` / `checked: boolean | "mixed"` / `expanded`）、`accessibilityValue`（`min` / `max` / `now` / `text`）。
- `disabled` 在每种宿主上都生效：挡住按压，读出 disabled 状态。
- 名字不自动从子节点算：图标按钮必须写 `accessibilityLabel`。嵌套 `Text` 的 span 不是原生视图，只在整段文本上设置。
- `testID` 仍然只是测试用的名字，不是无障碍 id。
- `BackHandler.addEventListener(handler)` 返回退订函数；handler 返回 `true` 表示已处理。新的监听先收到。Android 的返回键、返回手势，web 的 `popstate` 触发；没有人处理就按平台默认（Android 退到后台，web 正常后退）。iOS 不触发（没有系统返回）。web 上应用要自己 `history.pushState`（浏览器全局本来就可用）才有后退可听；v2 不替应用推历史条目。

v2 不做：无障碍动作、焦点顺序、播报、live region、分组与自动命名；web 的历史记录推入。

### 输入

- `multiline`：Return 插入换行，没有提交语义。文本按输入框宽度换行，高度由核心测出来的行数决定。
- `selectedRange: { start, end? }` 受控，单位是 UTF-16；`onSelectionChange({ start, end })` 在变化时报告。
- `onCompositionChange({ composing, text })`：输入法开始、变化、结束。组合期间的受控值不在 Android 上 `setText`，等组合结束再应用；事件顺序是先提交文本，再报组合结束。
- `type(selector, text)` 在 `--target` 走平台键盘，`\n` 是真的 Return；无窗口按协议逐次 `Change`。

v2 不做：`submitBehavior` / `returnKeyType`、`maxLength`、`onContentSizeChange`、输入法以外的附件视图、`Text` 的文本选择、可选中 `View`、行内视图、`href` / 打开外部链接。

### 发布

`nlayer package [--target web|ios|android]`，默认 `web`。应用根目录的 `nlayer.json`：

```json
{ "name": "Example", "id": "com.example.app", "version": "1.0.0", "build": 1, "icon": "./icon.png" }
```

- web：静态站（页面、`nlayer.wasm`、bundle、source map、按内容命名的资源），可直接托管。
- android：APK。manifest 用 `nlayer.json` 的 name / id / version / icon；默认 debug key，`--keystore` 用应用自己的。bundle 和资源打进 `assets/`，宿主从 `AssetManager` 读，不再从数据目录读。
- ios：设备架构的未签名 `.app`，bundle 和资源打进 `.app`，`Info.plist` 和图标来自 `nlayer.json`。签名、`.ipa`、商店元数据由应用自己做，CLI 只给出未签名的产物。
- 打包不新增 crate，代码在 `nlayer-cli`；`nlayer init` 写一份带占位 id 的 `nlayer.json`。
- 签名包（`.nshpkg`）不是这里的东西，仍是不预承诺。

## 公开模块

不变：只有 `@nlayer/runtime` 和 `@nlayer/ui` 两个原生模块，互不重导出。

`@nlayer/runtime` 增加：`resource`、`storage`。

`@nlayer/ui` 增加：`List`、`createAnimatedValue`、`Animated`、`BackHandler`、`platform.colorScheme`；`View` / `Text` / `Image` / `Scroll` / `Input` 的属性扩展无障碍、`disabled`、动效值；`Input` 增加 `multiline`、`selectedRange`、`onSelectionChange`、`onCompositionChange`；`onLongPress`、`delayLongPress` 进所有可按宿主。

`@nlayer/test`：`open(entry, { colorScheme, dataDir })`；选择器增加 `label:<文本>`、`role:<角色>[<名字>]`；`type` 支持换行。

类型仍由 `nlayer-bundler` 的 `gen-types` 生成到 `packages/`。

## 开发计划

每个里程碑是一个能合的切片：行为能跑，测试是绿的，没有空实现。改动到的 crate 跑 `cargo test -p`；动到 TSX、引擎或宿主的切片还要 `nlayer test` 绿。

### M1 数据通道

`resource`、`storage`、fetch 取消。

- `nlayer-core`：`resource` 的加载记账（哪一次加载算数、取代、取消、`mutate`），从 `nsh_core::resource` 裁。
- `nlayer-js`：`resource` 的 JS 面（render effect、promise 跟随、状态批量写），从 `nsh-js/src/resource.rs` 裁；`storage` 的 JS 模块（47 行）从 `nsh_core::runtime::storage` 裁；模块表加 `resource`、`storage`；prelude 加网络取消。
- `nlayer-engine`：`EngineConfig` 加数据目录和存储后端，`storage.rs` 文件后端从 `nsh-engine/src/storage.rs` 裁；网络请求可取消。
- 三端：iOS `Library/Application Support`、Android `getFilesDir()`、web `localStorage` 前缀、无窗口内存。
- web 页面：`runtime.js` 里用 `signal` / `effect` / `untracked` / `batch` 写一份 `resource`（约 70 行）；`storage` 用 `localStorage`。
- 测试：fixture server 的错误、取消、重载；存储配额；重启后读回。

来源：`nsh-core/src/resource.rs` 215、`nsh-js/src/resource.rs` 652、`nsh-core/src/storage.rs` 432、`nsh-core/src/runtime/storage.rs` 47、`nsh-engine/src/storage.rs` 423、`nsh-engine/src/net.rs` 575（取消部分）。

### M5 动效

图和绑定先落地，再接三端帧时钟。

- `nlayer-core`：`animation/{ops,graph,driver}.rs`（裁掉 composite / decay / settle / canvas / component slot）、`js/animation.rs` 的 easing 表（改成 nlayer 自己的声明生成器）；`Style` 的 `animated` 存进节点并转成绑定列表，`MountItem::Animation`（图 op）和 `MountItem::AnimationBindings`（属性到值）。
- `nlayer-engine`：`Message::Animation`（start / stop / set / read）与 `Message::AnimationFinished`；`MountSink` 反向通道。
- `nlayer-js`：`animated.rs` 的 JS 面（`AnimatedValue` 类、`interpolate` / `timing` / `spring`、`Animated` 命名空间、finalizer 释放），按 nlayer 的 `rquickjs` 写，不走 nsh 的 `HostValue`。
- iOS：`animation.rs`（134 行）裁到视图绑定，`CADisplayLink`，`Mounter` 每帧写属性，结束回报。
- Android：UI 线程的 Rust 图 + Java `Mounter` 的每帧应用（从 `nsh-platform-android/src/animation.rs` 383 与 `Mounter.java` 的 `Dynamic` 段裁）。
- web：`animation.rs`（281 行）裁到视图绑定，`requestAnimationFrame`。

### 顺序

M1、M2、M3、M6 互不依赖，可以并行；每个都只改自己需要的引擎通道和宿主文件。M4 先做（`ops.rs` / `core/mod.rs` / `mount.rs` 的改动最集中），M5 的纯图部分（`animation/` + 单测）可以在 M4 期间并行落地，接线等 M4 合入。M5 是 v2 唯一改三端帧循环的切片，放在最后验收。

## 不进 v2

| 项 | 为什么 |
|---|---|
| Nav / 栈 / 模态 / 转场 | 平台各一套原生容器与返回手势，XL；v2 只给 `BackHandler` |
| sticky header、`inverted`、`viewport="parent"`、viewability | 列表的第二层；先让基础窗口正确 |
| 下拉刷新、分页、吸附、缩放 | 三端各写一套手势/物理，和列表独立，v2.1 |
| pan / pinch / rotation 手势 | 需要触摸协商和动效图配合，v2.1 |
| 布局动画、样式过渡、keyframes、motion 预设 | 平台动画加数据表，等动效图和列表稳定 |
| Canvas | 需要布局尺寸事件、绘图 op 和三端重放，L |
| SVG / GIF | 原生解码依赖与播放生命周期；图标可先用位图 |
| Tailwind | 5k 行解析器，和现有 typed style 重复；v3 |
| WebSocket | 没有 tokio，且需要传输层和背压，XL |
| fetch cookie | nsh 也没有；安全和跨端语义要单独设计 |
| `crypto.subtle` | 现成实现带 Node `crypto` / `Buffer`，触碰永久不做 |
| HMR | 需要 CJS 工厂式开发包和状态保留，XL |
| 嵌入 ABI | XL，且与产品范围无关 |
| `Text` 文本选择、可选中 `View`、行内视图 | 三端各一套选择/手势栈，XL |
| 桌面、shader、自定义字体、签名包、`nlayer check` | 永久不做或不预承诺 |

## 风险与决定

- **动效图的归属**：v2 选 nsh 的做法，图在宿主线程，引擎只收发 op。代价是每个宿主多一条反向消息（`finished`、`get()`），收益是引擎忙时不掉帧。另一种做法是引擎线程逐帧跑图、每帧发 batch，省掉反向通道但把掉帧带进动画；不选。
- **Android 的图在 UI 线程**：nsh 的 Android 图是 Rust 在 UI 线程上、Java 读浮点输出。nlayer 的 mounter 是 Java，v2 照抄这个 JNI 形状，不写第二份 Java 图。
- **列表的布局根**：nlayer 现在从单一根布局，cell 独立 Taffy 根是 M4 的主要风险；先做这一项再谈回收。
- **一行两次动作**：长按之后松手不再发 `onPress`，避免一次手势触发两个动作；短按不变。
- **`disabled` 改变按压行为**：三种宿主都要一条测试，包括嵌套在可按祖先里的情况。
- **web 有两份实现**：QuickJS 宿主由引擎提供 `resource` / `storage` / `colorScheme`；web 由页面 facade 提供。两边同一套语义，各一条测试，防止漂移。
- **打包读取路径**：现在 Android 从数据目录、iOS 从数据容器读 bundle；改成从产物里读要和 `run` 的推送路径并存，不能破坏 v1 的热重启。
- **无障碍命名**：v2 只支持显式 label，不从子节点算名字；文档要写明，否则图标按钮在 VoiceOver 上是空的。
- **深色只到系统色**：没有 `dark:` 和自适应 token，应用要用 `platform.colorScheme()` 自己算样式；根界面跟随，但原生控件（键盘、滚动条、输入法）由系统决定。
